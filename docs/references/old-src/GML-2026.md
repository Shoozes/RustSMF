1\) Naming Conventions (PROJECT POLICY)

\- Local vars: prefix with underscore to avoid built-ins like x/speed.

&#x20; Example:

&#x20;   var \_loop = 0;

&#x20;   repeat (10) { \_loop++; }

\- Instance/global vars: lowercase\_with\_underscores.

&#x20; Example:

&#x20;   global.level = 1;

&#x20;   player\_health = 100;

\- Macros/enums: ALL\_CAPS\_WITH\_UNDERSCORES.

&#x20; Example:

&#x20;   #macro GRAVITY 9.81

&#x20;   enum STATE { IDLE, RUNNING }

\- Helper functions: double underscore prefix for internal/private-feeling helpers.

&#x20; Example:

&#x20;   function \_\_parse\_data(\_s) { return \_s; }

\- Function args: lowercase\_with\_underscores, leading underscore allowed.

&#x20; Example:

&#x20;   function calc(\_value) { return \_value \* 2; }

\- Arrays: loop indices use i, j, k without underscore for readability.

&#x20; Example:

&#x20;   for (var i = 0; i < array\_length(arr); i++) arr\[i] = 0;

\- Avoid camelCase in project code.

\- Prefer readable constants/macros for large values. Numeric separators are now supported, so 100\_000\_000 is acceptable when it improves readability.

\- Do not use emojis or decorative symbols in code, comments, filenames, or generated docs for this project.



2\) Garbage Collection (MANUAL CURRENT)

\- GC-managed: structs, arrays, methods, and other managed runtime values.

\- Not GC-managed in the same way: ds\_\* containers, buffers, surfaces, vertex buffers, vertex formats, cameras, shaders, and most explicit engine resources. Destroy/free/delete these through the correct API.

\- Arrays and structs are references. Losing all references allows GC cleanup, but contained explicit resources still need their own cleanup.

\- HTML5 target: browser JavaScript GC participates; do not rely on desktop-only GC tuning as a gameplay feature.

\- Controls and checks:

&#x20; - delete removes a variable reference and can help make GC-managed values collectible.

&#x20; - gc\_collect() can force collection at frame-end. Use sparingly.

&#x20; - gc\_target\_frame\_time(microseconds) sets a per-frame GC budget.

&#x20; - gc\_get\_stats() returns diagnostic information.

&#x20; - weak\_ref\_create(value) and weak\_ref\_alive(ref) help observe collected structs.

\- Avoid forcing gc\_collect() every frame. Fix ownership and cleanup first.



Example (Create, Step, Clean Up):

&#x20; // Create

&#x20; controller = { tick: 0 };

&#x20; buff = buffer\_create(1024, buffer\_fixed, 1); // manual cleanup



&#x20; // Step

&#x20; controller.tick++;

&#x20; if (keyboard\_check\_pressed(vk\_f1)) gc\_collect();



&#x20; // Clean Up

&#x20; delete controller;

&#x20; buffer\_delete(buff);



3\) Structs and Constructors (MANUAL CURRENT, SHIPPED LTS 2026.0 additions)

\- Structs: literal objects using { key: value }.

\- Struct access: dot syntax for known fields; st\[$ "field"] for dynamic field names.

\- Constructors: function Name(...) constructor { ... }.

\- Instantiate constructors with new Name(...).

\- Inheritance: function Child(...) : Parent(parent\_args) constructor { ... }.

\- Static members in constructors share code/data across all instances.

\- Useful introspection helpers:

&#x20; - variable\_struct\_get\_names(s)

&#x20; - variable\_struct\_exists(s, "field")

&#x20; - variable\_struct\_get(s, "field")

&#x20; - variable\_struct\_set(s, "field", value)

\- LTS 2026.0 adds shorter struct aliases:

&#x20; - struct\_get()

&#x20; - struct\_get\_names()

&#x20; - struct\_set()

&#x20; - struct\_exists()

&#x20; - struct\_remove()

&#x20; - struct\_names\_count()

\- LTS 2026.0 adds/extends:

&#x20; - struct\_foreach()

&#x20; - struct\_get\_from\_hash()

&#x20; - struct\_set\_from\_hash()

&#x20; - variable\_get\_hash()

&#x20; - variable\_clone()

&#x20; - static\_get()

&#x20; - static\_set()

&#x20; - is\_instanceof()

\- Use static\_set() carefully. It is mainly for deserialization-style use cases.

\- Static initialization behavior changed in LTS 2026.0. If an old project relied on re-entrant static initialization, refactor first. Use gml\_pragma("AllowReentrantStatic", true) only as a migration crutch.



Example:

&#x20; function Vec2(\_x = 0, \_y = 0) constructor {

&#x20;   x = \_x;

&#x20;   y = \_y;



&#x20;   static add = function(\_other) {

&#x20;     x += \_other.x;

&#x20;     y += \_other.y;

&#x20;   };

&#x20; }



&#x20; function Vec3(\_x = 0, \_y = 0, \_z = 0) : Vec2(\_x, \_y) constructor {

&#x20;   z = \_z;

&#x20; }



&#x20; var \_v = new Vec3(1, 2, 3);

&#x20; \_v.add(new Vec2(1, 1));

&#x20; var \_fields = struct\_get\_names(\_v);



4\) Arrays (MANUAL CURRENT)

\- Arrays are reference types by default.

\- Passing an array to a function and mutating it changes the caller's array unless legacy Copy on Write behavior is enabled.

\- Core ops:

&#x20; - array\_length

&#x20; - array\_push

&#x20; - array\_pop

&#x20; - array\_insert

&#x20; - array\_resize

&#x20; - array\_copy

&#x20; - array\_sort

&#x20; - array\_shuffle

&#x20; - array\_foreach

\- Performance:

&#x20; - Preallocate with array\_create(size, value) when size is known.

&#x20; - Cache array\_length() in tight loops.

&#x20; - For clear-and-refill, assigning a fresh array\_create(size, default\_value) is often cleaner than mutating every slot.

\- Legacy Copy on Write is deprecated behavior behind a project option. Do not rely on it for new code.

\- The @ accessor can bypass legacy Copy on Write for array writes, but in modern default behavior, normal array writes already mutate the referenced array.

\- Arrays can store handles, buffers, DS IDs, or surfaces, but the array being GC-managed does not destroy those explicit resources.



Example:

&#x20; function bump\_all(\_arr) {

&#x20;   var \_n = array\_length(\_arr);

&#x20;   for (var i = 0; i < \_n; i++) {

&#x20;     \_arr\[i] += 1;

&#x20;   }

&#x20; }



&#x20; var \_a = \[1, 2, 3];

&#x20; bump\_all(\_a);

&#x20; show\_debug\_message(\_a); // \[2, 3, 4]



5\) Accessors (MANUAL CURRENT)

\- DS list: list\[| index]

\- DS map: map\[? key]

\- DS grid: grid\[# x, y]

\- Array: arr\[@ index]

\- Struct: st\[$ "field"]

\- Accessors can be chained across different container types.

\- Prefer normal array\[index] unless maintaining legacy Copy on Write compatibility or intentionally using @ for a chained write.

\- Always destroy DS containers and nested DS resources manually.



Example:

&#x20; var \_data = \[ds\_list\_create(), ds\_map\_create()];

&#x20; \_data\[0]\[| 0] = ds\_grid\_create(4, 4);

&#x20; \_data\[0]\[| 0]\[# 2, 3] = 99;

&#x20; \_data\[1]\[? "meta"] = { ver: 1 };



&#x20; var \_ver = \_data\[1]\[? "meta"]\[$ "ver"];



&#x20; ds\_grid\_destroy(\_data\[0]\[| 0]);

&#x20; ds\_list\_destroy(\_data\[0]);

&#x20; ds\_map\_destroy(\_data\[1]);



6\) Variables and Scope (MANUAL CURRENT)

\- Local: var \_x; exists only inside the function/event scope.

\- Instance: x; field on the current instance.

\- Global: global.x; shared across the game.

\- Static: static x = value; stored on the function and persists across calls.

\- Dynamic instance access:

&#x20; - variable\_instance\_get(id, name)

&#x20; - variable\_instance\_set(id, name, value)

\- Dynamic global access:

&#x20; - variable\_global\_get(name)

&#x20; - variable\_global\_set(name, value)

\- Targeting other instances: with(id\_or\_object) { ... } or id.field.

\- Do not use built-in names like x, y, speed, direction as local variable names.



Example:

&#x20; hp = (is\_undefined(hp) ? 100 : hp);



&#x20; if (instance\_exists(obj\_enemy)) {

&#x20;   var \_enemy = instance\_find(obj\_enemy, 0);

&#x20;   variable\_instance\_set(\_enemy, "stunned", true);

&#x20; }



&#x20; function counter() {

&#x20;   static \_count = 0;

&#x20;   \_count++;

&#x20;   return \_count;

&#x20; }



7\) Matrix Functions, LTS 2026 3D Transforms (MANUAL CURRENT, SHIPPED LTS 2026.0)

\- Matrices do not have their own GML datatype; they are 16-value arrays.

\- Matrix values are stored in column-major order.

\- Core drawing matrices:

&#x20; - matrix\_world

&#x20; - matrix\_view

&#x20; - matrix\_projection

\- Build world transform:

&#x20; - matrix\_build(x, y, z, xrotation, yrotation, zrotation, xscale, yscale, zscale, \[result\_matrix])

\- Build view transform:

&#x20; - matrix\_build\_lookat(xfrom, yfrom, zfrom, xto, yto, zto, xup, yup, zup, \[result\_matrix])

\- Build perspective projection:

&#x20; - matrix\_build\_projection\_perspective\_fov(fov\_y, aspect, znear, zfar, \[result\_matrix])

\- Combine matrices:

&#x20; - matrix\_multiply(matrix1, matrix2, \[result\_matrix])

\- Invert matrix:

&#x20; - matrix\_inverse(matrix, \[result\_matrix])

\- Transform vector/point:

&#x20; - matrix\_transform\_vertex(matrix, x, y, z, \[w], \[result\_array])

\- Apply draw matrix:

&#x20; - matrix\_set(matrix\_world, matrix)

&#x20; - matrix\_set(matrix\_view, matrix)

&#x20; - matrix\_set(matrix\_projection, matrix)

\- Read draw matrix:

&#x20; - matrix\_get(matrix\_world)

&#x20; - matrix\_get(matrix\_view)

&#x20; - matrix\_get(matrix\_projection)

\- Matrix stack helpers:

&#x20; - matrix\_stack\_is\_empty()

&#x20; - matrix\_stack\_clear()

&#x20; - matrix\_stack\_set(matrix)

&#x20; - matrix\_stack\_push(matrix)

&#x20; - matrix\_stack\_pop()

&#x20; - matrix\_stack\_top()

\- Correction: use matrix\_stack\_set(), not matrix\_stack\_set\_top().

\- Matrix stack max size is 50. Always pop what we push.

\- matrix\_build() uses YXZ rotation order.

\- matrix\_build() returned matrices apply rotation first, then scale.

\- matrix\_multiply(matrix1, matrix2) returns matrix2 \* matrix1. Read transform order right-to-left.

\- matrix\_inverse() returns undefined when a new inverse cannot be returned because the matrix has no inverse.

\- Reuse optional result\_matrix/result\_array arguments in Step/Draw loops to reduce allocation churn.

\- On OpenGL platforms, projection matrix Y flipping is handled in Draw events. Avoid caching projection assumptions outside Draw without testing.



Example (obj\_control Create, reusable camera matrices):

&#x20; view\_visible\[0] = true;

&#x20; view\_camera\[0] = cam;

&#x20; cam\_y = -320;

&#x20; cam\_z = -160;

&#x20; cam\_yaw = 90;

&#x20; mat\_world = matrix\_build\_identity();

&#x20; mat\_world\_inverse = matrix\_build\_identity();

&#x20; world\_to\_local = array\_create(4, 0);



Example (obj\_control Step, manual 3D camera):

&#x20; var \_target\_y = cam\_y + lengthdir\_y(1, cam\_yaw);

&#x20; var \_target\_z = cam\_z;

&#x20;   \_target\_x, \_target\_y, \_target\_z,

&#x20;   0, 0, -1,

&#x20; matrix\_build\_projection\_perspective\_fov(

8\) Data Structures vs Arrays (MANUAL CURRENT, PROJECT POLICY)

\- Prefer arrays for general gameplay data:

&#x20; - GC-managed.

&#x20; - Fast iteration.

&#x20; - Easy nested tables using arr\[row]\[col].

&#x20; - Good for structs, components, transform lists, and small registries.

\- Use ds\_\* only when their semantics/API are worth the manual cleanup:

&#x20; - ds\_map for heterogeneous dynamic keys.

&#x20; - ds\_grid for large fixed 2D data with grid helper operations.

&#x20; - ds\_stack for LIFO.

&#x20; - ds\_queue for FIFO.

&#x20; - ds\_priority for priority queues.

\- Always destroy ds\_\* containers when done.

\- If DS containers store other manual resources, clean those nested resources before destroying or losing access.



Example (2D numeric table with arrays):

&#x20; var \_w = 64;

&#x20; var \_h = 64;

&#x20; var \_grid = array\_create(\_h);



&#x20; for (var j = 0; j < \_h; j++) {

&#x20;   \_grid\[j] = array\_create(\_w, 0);

&#x20; }



&#x20; \_grid\[10]\[20] = 1;



Example (map for heterogeneous keys):

&#x20; var \_map = ds\_map\_create();

&#x20; \_map\[? "name"] = "boss";

&#x20; \_map\[? 42] = true;

&#x20; ds\_map\_destroy(\_map);



9\) Pointers, References, and Handles (MANUAL CURRENT, SHIPPED LTS 2026.0)

\- References:

&#x20; - structs, arrays, methods, and handles are reference-like values.

&#x20; - delete removes a reference from a variable.

\- Pointers:

&#x20; - returned by low-level APIs such as buffer\_get\_address().

&#x20; - do not use after the resource is destroyed or resized.

&#x20; - pointer\_null means no useful pointer.

&#x20; - pointer\_invalid means invalid pointer.

\- Handles:

&#x20; - LTS 2026 represents many runtime resources as typed handles instead of plain numeric IDs.

&#x20; - Handle type checking helps prevent passing a DS list to a DS grid function, or another incompatible resource mismatch.

&#x20; - Resources can still be invalid. Use -1 for most invalid resource handles and noone for invalid instance handles.

&#x20; - Do not treat handles as sequential numbers. Resource index reuse can make stale handles dangerous after destruction.

&#x20; - Reset handle variables after manual destruction when they remain in scope.

\- LTS 2026.0 typed handles include buffers, vertex buffers, vertex formats, and surfaces.



Example:

&#x20; var \_buffer = buffer\_create(256, buffer\_fast, 1);

&#x20; var \_ptr = buffer\_get\_address(\_buffer);



&#x20; if (\_ptr != pointer\_null \&\& buffer\_exists(\_buffer)) {

&#x20;   // Pass pointer to extension code.

&#x20; }



&#x20; buffer\_delete(\_buffer);

&#x20; \_buffer = -1;

&#x20; \_ptr = pointer\_null;



10\) Modern 3D Rendering, LTS 2026 (MANUAL CURRENT, SHIPPED LTS 2026.0)

\- Use modern primitives, vertex buffers, shaders, matrices, and explicit GPU state.

\- Do not use legacy d3d\_\* assumptions.

\- Rendering pipeline:

&#x20; - vertex\_format\_begin()

&#x20; - vertex\_format\_add\_position\_3d()

&#x20; - vertex\_format\_add\_normal() when lighting needs normals

&#x20; - vertex\_format\_add\_texcoord() when textured

&#x20; - vertex\_format\_add\_color() when vertex colors are used

&#x20; - vertex\_format\_end()

&#x20; - vertex\_create\_buffer()

&#x20; - vertex\_begin()

&#x20; - vertex\_\* writes

&#x20; - vertex\_end()

&#x20; - optional vertex\_freeze() for static geometry

&#x20; - shader\_set()

&#x20; - matrix\_set()

&#x20; - vertex\_submit()

&#x20; - shader\_reset()

\- GPU state is global. Always restore state after custom draw passes.

\- Prefer gpu\_push\_state() and gpu\_pop\_state() around 3D passes.

\- For opaque 3D:

&#x20; - gpu\_set\_ztestenable(true)

&#x20; - gpu\_set\_zwriteenable(true)

&#x20; - gpu\_set\_zfunc(cmpfunc\_lessequal)

\- Defaults to remember:

&#x20; - z-test default is false.

&#x20; - z-write default is true.

&#x20; - zfunc default is cmpfunc\_lessequal.

&#x20; - cull mode default is cull\_noculling.

\- Backface culling:

&#x20; - Front side is defined by counter-clockwise vertex order.

&#x20; - Use cull\_noculling while validating imported/generated mesh winding.

&#x20; - Use cull\_clockwise or cull\_counterclockwise only after confirming triangle order.

\- Vertex buffers:

&#x20; - vertex\_freeze(vbuf) stores the buffer in VRAM and makes it read-only.

&#x20; - Use vertex\_freeze() only for static geometry.

&#x20; - Do not freeze buffers that need runtime updates.

&#x20; - LTS 2026.0 adds the ability to modify vertex buffers after creation/fill.

&#x20; - Use vertex\_update\_buffer\_from\_buffer() for buffer-to-vertex-buffer updates.

&#x20; - Use vertex\_update\_buffer\_from\_vertex() for vertex-buffer-to-vertex-buffer updates.

\- Surfaces:

&#x20; - surface\_create(width, height, \[format]) can now specify format.

&#x20; - Use surface\_format\_is\_supported(format) before non-default formats.

&#x20; - Use surface\_get\_format(surface\_id) when format must be validated later.

&#x20; - Non-application surfaces are volatile. Check surface\_exists().

&#x20; - Surfaces should normally be created and drawn to in Draw events.

&#x20; - Avoid drawing a surface to itself.



Example (Create, static triangle):

&#x20; vertex\_format\_begin();

&#x20; vertex\_format\_add\_position\_3d();

&#x20; vertex\_format\_add\_color();

&#x20; fmt = vertex\_format\_end();



&#x20; vbuf = vertex\_create\_buffer();

&#x20; vertex\_begin(vbuf, fmt);

&#x20; vertex\_position\_3d(vbuf, -1, -1, 0); vertex\_color(vbuf, c\_red, 1);

&#x20; vertex\_position\_3d(vbuf,  1, -1, 0); vertex\_color(vbuf, c\_green, 1);

&#x20; vertex\_position\_3d(vbuf,  0,  1, 0); vertex\_color(vbuf, c\_blue, 1);

&#x20; vertex\_end(vbuf);

&#x20; vertex\_freeze(vbuf);



Example (Draw, 3D pass):

&#x20; gpu\_push\_state();



&#x20; gpu\_set\_ztestenable(true);

&#x20; gpu\_set\_zwriteenable(true);

&#x20; gpu\_set\_zfunc(cmpfunc\_lessequal);

&#x20; gpu\_set\_cullmode(cull\_noculling);



&#x20; shader\_set(sh\_basic\_3d);

&#x20; matrix\_set(matrix\_world, matrix\_build(x, y, z, 0, current\_time \* 0.05, 0, 1, 1, 1));

&#x20; vertex\_submit(vbuf, pr\_trianglelist, -1);

&#x20; matrix\_set(matrix\_world, matrix\_build\_identity());

&#x20; shader\_reset();



&#x20; gpu\_pop\_state();



Example (Clean Up):

&#x20; vertex\_delete\_buffer(vbuf);

&#x20; vertex\_format\_delete(fmt);



11\) Error Handling (MANUAL CURRENT, PROJECT POLICY)

\- Use try/catch/finally around parsing, file IO, extension calls, JSON handling, and external data.

\- Use throw for our own controlled error objects/messages.

\- Use show\_error(message, abort) for critical development failures.

\- Prefer returning false/undefined from helper APIs when failure is expected and recoverable.

\- In LTS 2026.0, json\_parse() is stricter for strings starting with digits and trailing invalid data. Treat JSON input as untrusted.



Example:

&#x20; try {

&#x20;   var \_data = json\_parse(raw);

&#x20;   process\_save\_data(\_data);

&#x20; } catch (\_err) {

&#x20;   show\_debug\_message("Load failed: " + string(\_err.message));

&#x20; }



12\) Performance Notes (MANUAL CURRENT, SHIPPED LTS 2026.0, PROJECT POLICY)

\- Preallocate arrays with array\_create() when size is known.

\- Cache array\_length() in tight loops.

\- Reuse matrices and result arrays through optional result parameters where available.

\- Avoid allocating temporary structs/arrays in Draw unless the cost is known and acceptable.

\- Use get\_timer() or delta\_time for measurement.

\- Measure changes scientifically. Do not assume optimization wins without checking.

\- GC:

&#x20; - Set a reasonable gc\_target\_frame\_time() if needed.

&#x20; - Rely on incremental collection.

&#x20; - Only force gc\_collect() for tooling/profiling or controlled transitions.

\- Vertex buffers:

&#x20; - Freeze static vertex buffers.

&#x20; - Keep dynamic vertex buffers unfrozen.

&#x20; - Update dynamic data with vertex\_update\_buffer\_from\_buffer() or vertex\_update\_buffer\_from\_vertex().

\- Build/export:

&#x20; - LTS 2026.0 can automatically remove unused assets during compile when enabled.

&#x20; - Newly-created projects default that unused-asset removal option on; existing projects default off.

&#x20; - Use gml\_pragma("MarkTagAsUsed", tag\_name) or equivalent project setup when assets must be included despite dynamic lookup.

\- Function call optimization note:

&#x20; - LTS 2026 compiler optimization can affect overridden function behavior.

&#x20; - If a parent function calls another function expected to be overridden, use self.function\_name() or store the function as a method field.



Example:

&#x20; var \_t0 = get\_timer();

&#x20; var \_n = array\_length(a);



&#x20; for (var i = 0; i < \_n; i++) {

&#x20;   a\[i] += 1;

&#x20; }



&#x20; var \_ms = (get\_timer() - \_t0) / 1000000.0;

&#x20; show\_debug\_message("Loop ms: " + string(\_ms));



13\) Struct Initialization (PROJECT POLICY)

\- Initialize every field we plan to read later.

\- Avoid undefined fields in reusable constructors.

\- Use struct\_exists() or variable\_struct\_exists() when reading optional fields.

\- For 3D actors, initialize transform arrays/matrices up-front.

\- For manual resources, initialize handles to -1 or noone before creation.

14\) Project Structure and Single-Object Architecture (PROJECT POLICY)

\- Folders and groups in GameMaker are optional IDE organization. Runtime script/function availability is not based on folder paths.

\- Use a single control object, such as obj\_control or a unique control object name, to manage the game loop entry point.

\- Use one required room, such as rm\_main, as the minimal runtime room.

\- Favor constructors and structs for modular systems instead of many traditional objects when runtime instance overhead is unnecessary.

\- Asset prefixes:

&#x20; - sh\_ for shaders.

&#x20; - spr\_ for sprites.

&#x20; - fnt\_ for fonts.

&#x20; - rm\_ for rooms.

&#x20; - obj\_ for objects when using objects.

&#x20; - tex\_ for texture assets or runtime texture handles when helpful.

&#x20; - vfmt\_ for vertex formats when stored globally.

&#x20; - vbuf\_ for vertex buffers when stored globally or on structs.

\- Scripts use prefix\_purpose.gml without scr\_ prefix.

\- Group scripts in IDE folders for readability, but do not rely on folders as namespaces.

17\) Enums, Macros, Constants, Literals (MANUAL CURRENT, SHIPPED LTS 2026.0)

\- Enums:

&#x20; - Global identifiers holding constant integer values.

&#x20; - Good for state machines, switch cases, modes, asset semantic IDs, and finite states.

&#x20; - Syntax: enum NAME { MEMBER, MEMBER = VALUE }

&#x20; - Only integer values and expressions using prior enum values are valid.

&#x20; - Stored as int64s; is\_real() returns false.

&#x20; - Cannot be modified after creation.

\- Macros:

&#x20; - Global compile-time constant expressions.

&#x20; - Syntax: #macro NAME VALUE

&#x20; - No equals sign.

&#x20; - No semicolon.

&#x20; - Use config-specific overrides when needed: #macro ConfigName:NAME VALUE

\- Built-in constants:

&#x20; - pointer\_null

&#x20; - pointer\_invalid

&#x20; - undefined

&#x20; - infinity

&#x20; - NaN

&#x20; - noone

\- LTS 2026.0 code editor/compiler additions:

&#x20; - Binary literals: 0b0110.

&#x20; - Numeric separators: 100\_000\_000, 0xDEAD\_BEEF, 0b01101000\_01101001.

&#x20; - CSS-style color literals: #RRGGBB syntax.

&#x20; - Template strings: $"Value is {value}".

&#x20; - Struct shorthand: {apples, oranges, lemons: 7} expands to same-name fields.

18\) GML to DLL: Buffers, Pointers, and Quirks (PROJECT POLICY, MANUAL CURRENT)

\- GML external functions accept reals and strings. Complex payloads should use buffers.

\- If a function has 4 or more parameters, keep parameters real where required by the extension rules.

\- For text or complex payloads, prefer buffers over many arguments.

\- Pointers are passed as reals from GML.

\- In C/C++, cast double to uintptr\_t, then to void\*.

\- Treat GML strings as UTF-8 unless the extension explicitly defines another encoding.

\- Convert to UTF-16 in DLL code for Windows APIs when needed.

\- Build x64 unless targeting a specific platform/toolchain that requires otherwise.

\- Calling convention must match the extension definition.

\- buffer\_get\_address() returns an aligned base pointer.

\- Do not free GML memory in DLL code.

\- Do not resize buffers in DLL code.

\- Never write past buffer\_get\_size().

\- After buffer\_delete() or buffer resize, old pointers are invalid.



Usage patterns:

\- Input-only: GML writes bytes, passes pointer and size, DLL reads, returns code/number.

\- In/out buffer: GML preallocates capacity, DLL writes bytes, GML reads result.

\- Strings: prefer output buffers to avoid string lifetime issues.

\- Return const char\* only from stable storage if a string return is unavoidable.



Alignment, packing, endianness:

\- Runners are little-endian.

\- Match field order and endianness in C/C++.

\- Choose buffer alignment by field needs: 1, 2, 4, 8, or 16.

\- Use 8-byte alignment for 64-bit values.

\- Avoid C struct padding in binary protocols. Write explicit fields.

\- Prefer fixed-width C/C++ types.



Pitfalls:

\- Wrong convention can corrupt args/stack or fail silently.

\- x86 DLL with x64 runner fails to load.

\- Stale pointers after buffer\_delete() or resize can crash.

\- Returning stack strings creates dangling pointers.

\- Casting double directly to void\* risks truncation.



Numeric marshaling:

\- buffer\_u8/u16/u32/u64 maps to uint8\_t/uint16\_t/uint32\_t/uint64\_t.

\- buffer\_s8/s16/s32/s64 maps to int8\_t/int16\_t/int32\_t/int64\_t.

\- buffer\_f32/f64 maps to float/double.



Sanity checklist:

\- x64 build.

\- extern "C" \_\_declspec(dllexport).

\- Correct calling convention.

\- Pointer reals cast through uintptr\_t.

\- Validate pointer and capacity on entry.

\- Enforce bounds.

\- Do not free or resize GML memory.

\- Use one versioned buffer with opcode/length fields for complex APIs.

&#x20; - y down.

&#x20; - z depth.

23\) Surface Formats, HDR, and Post-Processing (SHIPPED LTS 2026.0)

\- surface\_create(width, height, \[format]) supports explicit formats.

\- Default format is surface\_rgba8unorm.

\- Useful formats:

&#x20; - surface\_rgba8unorm: default 8-bit RGBA.

&#x20; - surface\_r8unorm: single 8-bit red channel.

&#x20; - surface\_rg8unorm: two 8-bit channels.

&#x20; - surface\_rgba4unorm: compact 4-bit RGBA.

&#x20; - surface\_rgba16float: higher precision, useful for HDR-style rendering.

&#x20; - surface\_r16float: single-channel 16-bit float, useful for depth-like data.

&#x20; - surface\_rgba32float: highest precision RGBA, slower and less widely supported.

&#x20; - surface\_r32float: single-channel 32-bit float.

\- Always use surface\_format\_is\_supported() before creating non-default format surfaces.

\- Use surface\_get\_format() when later code depends on the actual format.

\- surface\_create() may create depth/stencil buffers when automatic depth buffer generation is enabled.

\- For post-processing, create surfaces at view/display size unless there is a strong reason for larger buffers.

\- Power-of-two surface sizes improve compatibility, especially for HTML5/devices.

24\) Shaders and Matrices (MANUAL CURRENT)

\- GameMaker sends world, view, and projection matrices to shaders through gm\_Matrices.
