Overview

This tool imports a GLB/GLTF file, extracts its meshes, textures, bones, and animations, and repacks them into a compact .smf binary format (v12). A React-based UI (no JSX) allows you to upload, preview, convert, and download—all in the browser. Recent updates (July 2025) resolved buffer overrun errors by implementing non-indexed triangle lists. Current development (July 2025) focuses on ensuring rig attachment and correcting skinning mismatches in the SMF editor, with ongoing debugging of bone transformations and dual-quaternions.

Setup & Serving

  • Clone or download the repo into a folder.
  • Important: index.html must be served via a local HTTP server to avoid CORS issues when loading binary assets. For example: 
    python -m http.server 8000
  • Open http://localhost:8000/ in a modern browser (must support ES modules).

Usage

  1. Click “Choose File” and select your .glb (or .gltf).
  2. The debug logger pane (bottom) will show load details:
    • Meshes found, textures extracted, bones & animations enumerated.
  3. Click “Export SMF” → this runs exportSMF() → returns a Blob-URL.
  4. Click “Download .smf” to save the binary file locally.

Key Modules

unpacker.js
  • Loads GLB via GLTFLoader.
  • Triangulates and converts to non-indexed triangle lists for SMF compatibility.
  • Prepares rig data by extracting bone hierarchies, logging transformations, and validating skinning attributes.
  • Extracts and deduplicates textures (canvas→dataURL).
  • Gathers per-mesh metadata: name, verts, triangles, texIdx.
  • Builds bone list and animation frames for export.
exporter.js
  • BinaryWriter auto-grows its buffer for dynamic data sizes.
  • Chunks: Header, Textures, Models, Rig, Animations.
  • Writes:
    • RGBA pixel data for each texture.
    • Per-vertex: pos / normal / uv / tangent / skinIndex / skinWeight (44 bytes per vertex).
    • Bone dual-quaternions, hierarchy flags, and transformations in the RIG chunk for skinning.
    • Animation keyframes (normalized time + per-bone DQ).
  • Patches header offsets once all chunks are built.
main.js (React UI)
  • Pure ES-Module, no JSX: uses React.createElement.
  • Manages state for meshesData, texturesData, bonesData, animsData, and smfUrl.
  • Wires up file input → unpackGLB → shows tables & previews.
  • “Export SMF” → calls exportSMF → shows download button.
ModelLoader.js & CustomSkeletonHelper.js
  • FBX/GLTF → baked transforms → normalized (180 units tall).
  • Custom skeleton overlay with bone-mid/joint markers & labels.
  • Useful for debugging bone orientations in Three.js scenes.
DebugLogger.js
  • Monkey-patches console.log/warn/error to an on-screen panel.
  • Adds timestamp, color-coding, and inline “suggestions.”
  • Very helpful for tracing texture, rig, skinning, and transformation export issues.

Common Pitfalls & Solutions

  • Missing Tangents: GLTF tangents aren’t always present. unpacker.js now computes tangents if needed.
  • CORS / Binary Loading: Must serve via HTTP (local server), otherwise the browser blocks GLTFLoader.loadAsync.
  • Texture Duplication: GLB data-URLs differ even if pixel-identical. We dedupe by comparing canvas.toDataURL().
  • Buffer Overrun: Previously caused by indexed geometry. Resolved by converting to non-indexed triangle lists in unpacker.js (July 2025 update).
  • Rig Attachment Issue: Rig loads but may not bind to the mesh. Under investigation (July 2025) for bone index mapping, dual-quaternion inconsistencies, or transformation errors. Debugging transformations and IK rotations ongoing.
  • Skinning Mismatch: Vertex weights may not align with SMF expectations. Debugging ongoing to correct weight normalization, bone binding, and index mapping.
  • Animation Synchronization: We build the unique, sorted key-time list from all position/quaternion/scale tracks, then sample the mixer at exactly those times.
  • Buffer Growth: Large models can exceed initial buffer sizes. Our BinaryWriter auto-grows by 1 KB + needed bytes.
  • React Syntax: The UI is not JSX—if you see “Unexpected token <” it means you accidentally tried JSX in a raw type="module" file.
