# RustSMF App State

Last reviewed: 2026-06-30 (animation clip metadata controls, snap controls, clip CRUD/reorder, timeline marker interaction, skin paint/indexing, transform ownership, and global history-order fixes).

## Current Product State

RustSMF is a Tauri + React + Three.js desktop/web model tool for SMF, GLB/GLTF, FBX, and OBJ workflows.

Core flow:
- Launch from `.\run.bat` or `pwsh -File run.ps1`; no-argument launch opens the numbered menu. Choose option 2, or run `.\run.bat 2` / `pwsh -File run.ps1 -Task run`, to start the desktop app when dependencies are already installed.
- Load `.smf`, `.glb`, `.gltf`, `.fbx`, and `.obj` through browser input, drag/drop, or Tauri native dialog.
- The Outliner derives real model items from the loaded Three root, shows mesh/group counts, material color swatches, vertex/material hints, selected row state, and display-only submodel visibility toggles. It supports row multi-select, Select All, Clear, Hide selected, Hide unselected, Show all, View-mode viewport mesh picking/context readiness against the same model item list, viewport-only selection overlays for selected visible objects, and toolbar/keyboard undo-redo for visibility transactions. App-level Undo/Redo now chooses the newest available editor, skin, or outliner transaction by shared chronology instead of current workspace bias.
- Render model roots in a self-contained Three.js viewport with orbit, wheel zoom, right-drag pan, reset, lighting, grid, axes, model-safe wireframe render override, resize handling, and cleanup.
- Viewport layout controls are model-aware: with no model loaded, layout is forced to single-view (`data-viewport-layout="single"`); single/quad layout controls become active after a model is loaded. Camera mode is exposed as a compact 3D/Ortho switch, with single-view orthographic framing sized to the active canvas. Quad view is visually explicit with pane dividers and Top/3D/Front/Side labels.
- Mode/workspace switching is continuity-checked in normal, medium, and constrained-width viewports; narrow layouts put mode tabs on a scrollable row, and layout switching remains disabled until a model is loaded.
- Launcher contract (current):
  - `run.bat` / `run.ps1` are the canonical Windows workflow and carry full orphan-prevention coverage.
  - `run.ps1 -Task run` (same as launcher option 2) is the default app launch path after setup.
  - `run.ps1 -Task test:e2e` uses GenEye as an optional advisory Playwright subagent when discoverable, but RustSMF remains able to run browser-only e2e with `-NoGenEye`, `RUSTSMF_NO_GENEYE=1`, or no GenEye checkout/runtime.
  - Direct `npm run dev` / `npm run tauri:dev` flows remain available but intentionally have reduced non-canonical lifecycle guarantees.
- Drive animation through viewport-owned `AnimationMixer` state with timeline play/pause, scrub, speed, clip selection, imported keyframe markers, lane click-to-scrub, double-click selected-bone key insertion, authored marker drag-to-time, and an Animate workspace summary for active clip/selected-bone tracks.
- Manage the active animation clip from the Animate workspace with rename, duplicate, guarded delete, Move Up/Move Down reorder, loop toggle, and sample frame multiplier controls. Clip CRUD/reorder/metadata edits update the base clip list or metadata edit layer, authored animation edit keys where applicable, active playback clip/time, and toolbar/Ctrl+Z/Ctrl+Y editor history together; delete is disabled for the final remaining clip and reorder buttons are disabled at list boundaries. SMF-source exports rebuild animation lists when clips are renamed, duplicated, deleted, or reordered instead of silently preserving the original source list/order, and loop/sample metadata is preserved through SMF-source plus non-SMF-to-SMF export candidates.
- Author selected-bone animation keys for position/quaternion tracks through the Animate workspace: Insert, Update, Delete, Copy, Paste, Linear/Step interpolation, and seconds-based Snap controls update an edit layer, rebuild runtime `AnimationClip` tracks, drive the viewport mixer, feed supported SMF export/check paths, and support toolbar/Ctrl+Z/Ctrl+Y undo-redo for key Insert/Update/Delete/Paste plus interpolation changes. Snap is off by default and, when enabled, applies consistently to scrub/insert, paste, authored marker drag-to-time, and Animate-owned viewport key creation.
- Validate, rename, reparent, create child bones, and delete unweighted non-root branches for loaded non-SMF rigs in the Rig workspace. The Rig panel reports bone and skinned-mesh counts plus pass/warning/error rows for missing skeletons, duplicate bone names, orphan parents, self-parent/cycle hazards, incomplete skin attributes, mismatched skin attributes, and skin indices that reference missing bones. Selected-bone rename is enabled for non-SMF sources and retargets runtime animation tracks, authored animation key edits, pose edit keys, and selected skin-paint bone state together. Selected-bone reparent is enabled for non-SMF sources, rejects cycles/self-parenting, and preserves the bone world transform while changing hierarchy. Selected-bone create child is enabled for non-SMF sources, validates unique names, initializes inverse bind data, refreshes Skeleton buffers, selects the new child, and remains exportable through the generated-skinned SMF roundtrip path. Selected-bone delete blocks roots and weighted skin references, compacts Skeleton data, remaps surviving skinIndex attributes, removes deleted animation tracks/authored keys/pose edits, and selects the deleted bone's parent. Non-SMF rig rename/reparent/create/delete actions now use toolbar/Ctrl+Z/Ctrl+Y undo-redo snapshots that restore skeleton bones, parent links, inverse binds, skin indices, base clips, authored animation edits, pose edits, selected bone, and selected skin-paint state. SMF-source node rename/reparent/create/delete edits are blocked to preserve node-index and head-node export fidelity.
- Inspect skeletons, select bones from the hierarchy or routed viewport clicks, show larger diamond/joint skeleton helpers, show a selected-bone marker, use TransformControls in owned authoring modes, use quick nudges in Rig/Skin, and toggle selected-bone weight preview. `viewportInteractionRouter.ts` now gives pointer-down interactions a tested owner (`model-select`, `rig-select`, `rig-endpoint-drag`, `skin-paint`, `animate-select`, `orbit`, or `none`) before the viewport mutates state, while TransformControls expose separate `data-transform-owner`, `data-transform-attached`, and `data-transform-dragging` telemetry. View-mode `model-select` clicks raycast visible meshes into Outliner selection, empty plain clicks clear model selection, and right-click prepares a model-item context action status without opening browser context UI. TransformControls are explicit owner paths: Rig/Skin record pose edits, Animate records animation keyframes at the current timeline time, and View/Export detach/disable the gizmo. Endpoint drags still emit typed viewport transform edit events back into the app state, so SMF-source viewport pose edits are export-tracked instead of silently mutating Three objects only. Pose transactions for quick nudges, TransformControls, and endpoint drags now use the shared editor history helper, with toolbar Undo/Redo and Ctrl+Z/Ctrl+Y restoring both local Three bone transforms and the pose edit map used by SMF export. Animate-owned TransformControls use the shared animation history snapshot path, so Undo/Redo restores authored key state instead of pose state. Weight preview now shares the same four-slot skin-weight reader used by the tested edit helpers. Viewport skin painting now supports set/add/subtract/Auto brush modes with selected-bone prerequisite, vertex/triangle brush targets, brush hover markers that stay inactive on empty-space misses, radius/strength/falloff controls, skinned-world CPU brush candidate indexing, projected-depth rejection, 50 fps drag throttling, undo/redo stroke checkpoints, full-model Normalize, and Auto Skin batch actions with precise algorithm/options controls (segment inverse distance, segment distance + normals, nearest segment, nearest bone origin, closest two segments, selected branch, power, normal weighting, max influences). Legacy algorithm ids still normalize for compatibility. Skin edit snapshots are reachable from local Skin buttons plus toolbar Undo/Redo and Ctrl+Z/Ctrl+Y in Skin mode, preserve state continuity across workspace transitions, and serialize dirty skin edits for supported SMF export.
- Move selected bone endpoint markers in precision modes with camera-plane constrained drag (no model swap, no control conflict), and endpoint-drag lifecycle assertions are covered by e2e smoke in single and quad modes, including pose-dirty app-state propagation.
- Export SMF sources through the high-fidelity SMF roundtrip path, including live position/rotation pose edits from inspector nudges, TransformControls, and endpoint drags. SMF scale mode is refused in the UI, and any recorded non-identity pose scale blocks SMF export/roundtrip instead of being dropped.
- Export compatible skinned GLB/FBX runtime roots to SMF through `threeToSmf`; use GLB export for static/material/scale cases.
- Export FBX-loaded runtime roots to binary FBX 7500 through the vendored MIT `FBXExporter-threejs` writer; static binary output is covered by a header and loader roundtrip unit test.
- Run structured SMF compatibility diagnostics before non-SMF SMF export. The Export workspace reports ready/blocked state, diagnostic error/warning counts, and specific issues such as missing skeletons, unsupported scale tracks, missing UVs/normals, missing skin attributes, non-power-of-two textures, multi-material meshes, and multi-texture material layouts. It also shows a compact material texture list with map type, name, mesh/material slot, resolution, power-of-two status, and runtime source. The Export workspace can run an in-memory SMF roundtrip check that exports, reimports, compares summary counts, geometry, bounds, animation timing/metadata, first/last-frame pose checks, and the top worst pose-delta rows with animation/frame/bone, parent/isBone, and component-delta details, then save the diagnostics/roundtrip report through the existing save bridge.
- Cover default non-SMF skinned load/export e2e with a generated self-authored skinned GLB fixture.
- Cover basic FBX parsing with a self-authored static ASCII FBX fixture, and true binary FBX export with a self-authored static scene unit roundtrip.
- Use Rust/Tauri commands for native open/save, binary read/write, and small SMF header/rig/anim/model validation/status peeks. Desktop open is format-aware: all path-backed non-SMF models now route through `readBinaryFile`, while `.smf` still performs `get_smf_desktop_info` validation before parse. Rust SMF header/section parsing now lives in `source/src-tauri/src/smf_core.rs` with typed `SmfHeaderSummary` / `SmfDesktopInfo` output and tests for missing terminators, bad versions, invalid offsets, valid fixtures, and count-width behavior.
- Ignore stale file-open and browser file/drop read results when a newer operation has started (covered by native mocked-open/rapid-export checks and browser file-input/drop overlap smoke assertions).
- Keep editor mode + viewport layout transitions on the same shared model/viewport root; selected bone and scrub/timeline state are preserved across those transitions and now covered by smoke assertions.
- Keep constrained-width workspace tabs deterministic after model load; the 360px smoke path clicks Model/Rig/Skin/Animate/Export without forced clicks and verifies selected bone plus scrub continuity.
- Model/load/export async failures in `useLoadModel` normalize unknown error values through a single helper; GLB/FBX skinned traversal, viewport transform edit events, TransformControls drag events, and Three disposal boundaries use typed guards instead of broad production `any` casts.
- `run.ps1 -Task verify` and `npm run verify` now include `check:production-any`, which fails new production `as any`, `: any`, or typed-catch `any` usages outside tests and vendored code.
- Modernization keeps the current React/Tauri/Three stack, uses GLB/GLTF as the preferred modern fidelity format, and preserves SMF for backwards compatibility. Old GameMaker screenshots/scripts now guide the remaining authoring parity work: quadratic animation interpolation policy/runtime behavior, SMF head-node-aware rig metadata edits, rig detach/connect and mirror/reset helpers, and deeper ortho-pane editing controls. Quad layout, pane labels/dividers, model-safe wireframe display, viewport-only Legacy SMF-lit display materials, skinned vertex point overlays, viewport-only selected-object overlays, grouped Display menu toggles, submodel visibility/color cues, endpoint handles, imported/authored keyframe markers, timeline lane gestures, loop/sample clip metadata controls, autoskin algorithm/options controls, Auto Paint brush mode, skinned-world brush indexing, normalize batch tools, Rig validation/rename/reparent/create/delete with undo-redo, and pane-aware timing are current editor affordances covered by e2e/visual checks.

## Architecture

- `source/frontend/src/App.tsx`: thin shell wiring toolbar, viewport, inspector, timeline, outliner, drop zone, status, error banner, derived outliner items, active animation keyframe summaries, and animation authoring handlers.
- `source/frontend/src/hooks/useLoadModel.ts`: load/export orchestration, source format tracking, Tauri lazy imports, load/open stale guards, selected bone handling, pose edit persistence, viewport transform edit handling, shared pose/rig/animation-key/animation-workspace history snapshot/apply wiring, SMF scale-edit blocking, transform mode, and weight preview state.
- `source/frontend/src/hooks/useLoadModel.ts`: loader path now resolves a typed `TauriClient` contract (`../backend-client/tauri`) and uses a shared typed `LoadedModelResult`, reducing `any` usage across load/export/peek branches.
- `source/frontend/src/hooks/useLoadModel.ts`: in-flight export/save guard (`isExportingRef` + export seq guard) serializes export actions during async save/write and blocks stale completions.
- `source/frontend/tests/native.spec.ts`: added Playwright native IPC race coverage for delayed native saves to prove single-flight export behavior and status-button recovery under rapid click.
- `source/frontend/src/hooks/poseEdits.ts`: nudge delta types, dirty absolute-edit flags, unsupported scale flags, and helpers for live SMF position/rotation edits.
- `source/frontend/src/utils/editorHistory.ts`: shared bounded undo/redo stack helper currently used by pose authoring, non-SMF rig edits, selected-bone animation key edits, and Outliner visibility transactions; it carries ordering metadata so app-level toolbar/keyboard Undo/Redo can route by newest transaction across editor, Skin, and Outliner stacks.
- `source/frontend/src/components/ThreeViewport.tsx`: renderer, scene, camera, orbit, model attach/dispose, mixer, modern skeleton helper, helper-mesh/raycast bone picking, marker, TransformControls, typed transform edit event emission, model-safe wireframe render override, and weight preview.
- `source/frontend/src/utils/modernSkeletonHelper.ts`: typed port of the useful old helper idea, drawing larger diamond bone spans and joint markers with bone metadata for direct helper-hit selection.
- `source/frontend/src/utils/legacySmfLighting.ts`: viewport-only SMF-lit display material clone helper for the Display menu Legacy mode; original/export materials are restored and not mutated by the display toggle.
- `source/frontend/src/utils/skinPointOverlay.ts`: viewport-only skinned vertex point overlay for the Display menu Skin pts mode; points are sampled from skin attributes and colored by selected-bone influence without changing mesh/export data.
- `source/frontend/src/utils/selectionOverlay.ts`: viewport-only selected-object BoxHelper overlays for Outliner/model-pick selection state; overlays are not attached to export data and are rebuilt when selection or submodel visibility changes.
- `source/frontend/src/utils/skinWeights.ts`: pure skin-weight edit helpers and `SkinEditState` model for reading, setting, adding, subtracting, clamping, normalizing, typed Auto Skin/Auto Paint algorithms/options, touched-vertex snapshots, dirty tracking, and producing an explicit dirty-export block reason before UI/export wiring.
- `source/frontend/src/utils/skinBrushIndex.ts`: CPU cell indexes for bounded brush candidate queries in local bind space and skinned world space; `ThreeViewport` uses the skinned-world path for active Skin paint queries and still verifies candidates with world-space radius/depth checks before painting.
- `source/frontend/src/utils/rigValidation.ts`, `source/frontend/src/utils/rigEdits.ts`, and `source/frontend/src/components/RigPanel.tsx`: pure rig validation, selected-bone rename validation/animation retargeting, selected-bone reparent validation/world-transform preservation, selected-bone create-child validation/Skeleton initialization, selected-bone delete validation/Skeleton compaction/skinIndex remapping, and Rig workspace report/edit rows for skeleton graph and skin-reference hazards.
- `source/frontend/src/components/Inspector.tsx`: typed skeleton tree, clip list, selection controls, transform mode controls, and nudge controls.
- `source/frontend/src/components/Outliner.tsx`: model-derived submodel list with multi-select, display-only visibility toggles, bulk visibility actions, toolbar/keyboard visibility undo-redo, and material/color cues.
- `source/frontend/src/components/Timeline.tsx` / `source/frontend/src/components/AnimatePanel.tsx`: playback controls, scrub/keyframe lane, lane click-to-scrub, double-click selected-bone insertion, authored marker drag-to-time, selected-key state, imported/authored keyframe markers, active clip/selected-bone summary, keyframe authoring controls, Snap authoring control, and active-clip rename/duplicate/delete/reorder controls.
- `source/frontend/src/components/ExportPanel.tsx`: source-format and skeleton summary, structured SMF diagnostics for export preflight, material texture summary rows, in-memory SMF roundtrip status/check rows, worst-pose-delta detail rows, and diagnostic report save control.
- `source/frontend/src/utils/viewportLayout.ts`: shared single/quad viewport pane math, ortho camera framing, and pointer coordinate conversion helpers used by `ThreeViewport.tsx`.
- `source/frontend/src/utils/viewportInteractionRouter.ts`: pure pointer-owner router for mode-specific viewport click/drag intent; currently wired for telemetry, Rig/Animate bone selection, Rig endpoint drag, Skin paint gating, Model workspace placeholder ownership, and Export read-only left clicks.
- `source/frontend/src/utils/modelOutliner.ts`, `source/frontend/src/utils/textureCompat.ts`, `source/frontend/src/utils/animationTimeline.ts`, and `source/frontend/src/utils/animationEdits.ts`: pure helpers for model tree summaries, material/texture compatibility summaries, imported clip keyframe summaries, editable animation keyframes, clip edit-state helpers, runtime clip rebuilding, and SMF-source dirty animation/list patching.
- `source/frontend/src/loaders/*` and `source/frontend/src/vendor/FBXExporter.js`: SMF import/export (buildThreeScene delegates rig to buildRigHierarchy for flat nodes + isBone=0 head dummies: cycle-safe effective-parent walk skips heads for direct real-bone .add() + deform-only Skeleton; bind locals use nearest real ancestor world for correct matrixWorld; inverse binds are calculated after world matrices update; animation tracks are emitted only for real scene bones; names `SMF_Node_N` + userData; skin remap direct on compressed is-bone seq), bounded binary helpers, rig node-list helper (export), structured SMF diagnostics, guarded Three-to-SMF conversion, GLB/FBX/OBJ loading/export, binary FBX 7500 export, coordinate swizzles, and DQ math. `dqNormalize` falls back to identity for zero/NaN/Infinity rotation parts. SMF rig tree now produces clean SkeletonHelper/Inspector/picker for rigs with disconnected parts (skin/anim/export fidelity preserved via world DQ + compose).
- `source/frontend/src/backend-client/tauri.ts`: `TauriClient` interface now centralizes shared desktop bridge function contracts for load/export/peek calls, and `useLoadModel.ts` consumes it directly.
- `source/frontend/src/backend-client/tauri.ts`: browser/Tauri bridge for dialog, save, binary read, invokes, and desktop fallback messages. `saveFile` returns `boolean` so cancel is explicit.
- `source/frontend/src/utils/modelFormat.ts`: canonical format extension parser + shared extension constants for open/load/tauri filters.
- `source/frontend/tests/helpers/skinned-glb-fixture.ts`: generated self-authored skinned GLB fixture for default non-SMF skinned e2e coverage.
- `source/frontend/src/store`: lightweight React state slices for model, playback, and UI.
- `source/src-tauri/src/main.rs` and `source/src-tauri/src/smf_core.rs`: Tauri commands plus the Rust SMF header/section parser core, desktop summary struct, and native parser tests.
- `source/backend`: reserved boundary only; no current backend service is required.
- Launchers + dev server lifecycle (`run.ps1` / `run.bat` default, `source/frontend/scripts/start-vite-dev.mjs` beforeDev wrapper, `source/src-tauri/tauri.conf.json`): safe child process handling (Windows JobObject KILL_ON_JOB_CLOSE + recursive tree kill + port 5173 + cmdline sweeps + entry stale reaper + signals + finally/traps + parent poll) so closing the cmd window or Tauri app does not leave rogue node/Vite servers. Tauri CLI term of beforeDev triggers mjs cleanup; launcher owns the outer tree. (See PITFALL for the pre-fix rogue class and summary_bank subsystem__dev_process_lifecycle.)

## Verification

- Primary commands:
  - `pwsh -File run.ps1 -Task verify`
    - Runs context-bank validation, lint, app/test typecheck, production `any` boundary check, build, chunk guard, frontend units, and Rust cargo check.
  - `pwsh -File run.ps1 -Task test:e2e`
    - `test:e2e` passes RustSMF's Playwright command to GenEye `playwright-full -AllowGenEyeFailure -Group geneye-watch-fixture` when GenEye is discoverable (`-GenEyeRoot`, `GENEYE_ROOT`, `GENEYE_RUN_BAT`, or local Three-Sisters path). Evidence is ignored under `runtime-data\geneye-playwright-runs\`; RustSMF app evidence is the GenEye `project_tests` block plus discovered RustSMF Playwright artifacts, while the built-in GenEye scenario only proves advisory plumbing. Use `-NoGenEye` or `RUSTSMF_NO_GENEYE=1` for browser-only e2e. If GenEye is unavailable or fails before project-test evidence exists, the launcher runs browser-only Playwright. RustSMF project-test failures stay authoritative.
    - The launcher now emits one stable status trailer before final return: `[GENEYE] run_path=... project_tests.status=... project_tests.exit_code=...`, so consuming logs can parse authoritative project status without opening JSON.
  - `pwsh -File run.ps1 -Task test:visual-strict` (opt-in)
  - `pwsh -File run.ps1 -Task test:visual-update` (intentional baseline refresh only)
  - `pwsh -File run.ps1 -Task desktop-smoke`
  - `python scripts/verify-context-bank.py`
  - `npm audit --omit=optional`

## Current Limits

- Native UI roundtrip automation is covered through deterministic Playwright Tauri IPC mocks plus Rust command tests; true OS dialog automation is deferred until a dialog-only bug, CI requirement, or release checklist needs it.
- Default non-SMF skinned coverage uses a generated skinned GLB fixture. FBX coverage uses a self-authored static ASCII FBX fixture for parser coverage plus a generated static scene for binary FBX export roundtrip; skinned FBX fidelity still needs a dedicated redistributable skinned FBX asset if that path becomes important.
- GLB/FBX-to-SMF conversion is available for skinned models with one shared named skeleton and no scale animation. Static roots, textures/materials, morph tracks, object-level tracks, and scale animation still use GLB export for fidelity. SMF diagnostics now block known impossible exports before save, surface warnings for material/texture compatibility risks that do not block, show texture source summaries, and provide a structured in-memory roundtrip check for count, geometry, bounds, animation timing/metadata, first/last-frame pose deltas, and bounded worst-pose-delta details. Real imported SMF samples can still expose strict pose-delta mismatches; those are now classified in the cockpit but not yet root-caused.
- GLB/GLTF remains the preferred format for maximum fidelity and new development. SMF support is scoped to legacy recovery and users who target the old SMF binary pipeline.
- Live SMF position/rotation pose edits export; scale edits are blocked for SMF export because the current SMF DQ path has no scale channel. The UI refuses SMF scale mode, and export/roundtrip guards also catch recorded non-identity scale.
- Quad layout, ortho camera panes, single-view Ortho, visible pane labels/dividers, model-safe wireframe display, Legacy SMF-lit viewport display, Skin pts vertex overlay, selected-object viewport overlays, grouped Display menu toggles, Outliner submodel visibility/color cues, Outliner multi-select/bulk visibility with undo-redo, View-mode model/submodel picking, larger diamond/joint rig helpers, oversized selected-bone endpoint handles, imported/authored keyframe markers, timeline lane click-to-scrub, double-click selected-bone insertion, authored marker drag-to-time with optional snap, selected-bone keyframe authoring with toolbar/keyboard undo-redo, active-clip rename/duplicate/delete/reorder/loop/sample metadata controls with toolbar/keyboard undo-redo, Animate-owned viewport transform key authoring, Rig validation/rename/reparent/create/delete with toolbar/keyboard undo-redo, endpoint drag interactions, pointer-owner routing, transform-owner telemetry, app-level chronological Undo/Redo across editor/Skin/Outliner stacks, and pose undo/redo for nudges/gizmo/endpoint edits are implemented and covered by focused e2e/visual checks. Skin paint authoring now covers stroke undo/redo through local controls plus toolbar/Ctrl+Z/Ctrl+Y, empty-space miss safety, Auto Paint brush mode, skinned-world brush candidate indexing, vertex/triangle targets, autoskin algorithm/options, normalize batch actions, state continuity, and supported export behavior; quadratic animation interpolation behavior, direct browser-level TransformControls handle-drag automation, real-SMF strict pose roundtrip cleanup, SMF head-node-aware rig metadata edits, rig detach/connect and mirror/reset helpers, and deeper ortho-pane editing parity remain planned.
- Launcher process safety (no rogue node servers on close) is Windows-primary via run.ps1 + mjs layers (Job/tree/scans/poll). Direct `tauri dev` or non-Windows have reduced coverage (mjs signals + polls + child-tree cleanup where supported); behavior is documented explicitly in launcher docs.
