# RustSMF App State

Last reviewed: 2026-07-13 (verified constrained Rig IK, atomic pose history/cancel, SMF roundtrip, GLB reparse validation, and reviewed visual proof; stored-world-pose/head-node protections remain current).

## Current Product State

RustSMF is a Tauri + React + Three.js desktop/web model tool for SMF, GLB/GLTF, FBX, and OBJ workflows.

Core flow:
- Launch from `.\run.bat` or `pwsh -File run.ps1`; no-argument launch opens the numbered menu. Choose option 2, or run `.\run.bat 2` / `pwsh -File run.ps1 -Task run`, to start the desktop app when dependencies are already installed.
- Load `.smf`, `.glb`, `.gltf`, `.fbx`, and `.obj` through browser input, drag/drop, or Tauri native dialog.
- The Outliner derives real model items from the loaded Three root, shows mesh/group counts, material color swatches, vertex/material hints, selected row state, and display-only submodel visibility toggles. It supports row multi-select, Select All, Clear, Hide selected, Hide unselected, Show all, View-mode viewport mesh picking/context readiness against the same model item list, viewport-only selection overlays for selected visible objects, and toolbar/keyboard undo-redo for visibility transactions. App-level Undo/Redo now chooses the newest available editor, skin, or outliner transaction by shared chronology instead of current workspace bias.
- Render model roots in a self-contained Three.js viewport with orbit, wheel zoom, right-drag pan, reset, lighting, grid, axes, model-safe wireframe render override, resize handling, and cleanup.
- Viewport layout controls are model-aware: with no model loaded, layout is forced to single-view (`data-viewport-layout="single"`); single/quad layout controls become active after a model is loaded. Camera mode is exposed as a compact 3D/Ortho switch, with single-view orthographic framing sized to the active canvas. Quad view is visually explicit with pane dividers and Top/3D/Front/Side labels. At narrow widths, an open Display menu stays in the toolbar flow so it does not overflow horizontally or cover quad pane labels. Shared pane hit math now uses deterministic half-open internal boundaries, inclusive outer canvas edges, CSS-coordinate normalization that remains stable under high-DPI backing buffers, and browser-visible `data-viewport-pane-role` telemetry for the pane hit by the latest routed pointer event.
- Mode/workspace switching is continuity-checked in normal, medium, and constrained-width viewports; narrow layouts put mode tabs on a scrollable row, and layout switching remains disabled until a model is loaded.
- Launcher contract (current):
  - `run.bat` / `run.ps1` are the canonical Windows workflow and carry full orphan-prevention coverage.
  - `run.ps1 -Task run` (same as launcher option 2) is the default app launch path after setup.
  - `run.ps1 -Task test:e2e` uses GenEye as an optional advisory Playwright subagent when discoverable, but RustSMF remains able to run browser-only e2e with `-NoGenEye`, `RUSTSMF_NO_GENEYE=1`, or no GenEye checkout/runtime.
  - Direct `npm run dev` / `npm run tauri:dev` flows remain available but intentionally have reduced non-canonical lifecycle guarantees.
- Drive animation through viewport-owned `AnimationMixer` state with timeline play/pause, scrub, speed, clip selection, imported keyframe markers, lane click-to-scrub, double-click selected-bone key insertion, authored marker drag-to-time, and an Animate workspace summary for active clip/selected-bone tracks.
- Manage the active animation clip from the Animate workspace with rename, duplicate, guarded delete, Move Up/Move Down reorder, loop toggle, and sample frame multiplier controls. Clip CRUD/reorder/metadata edits update the base clip list or metadata edit layer, authored animation edit keys where applicable, active playback clip/time, and toolbar/Ctrl+Z/Ctrl+Y editor history together; delete is disabled for the final remaining clip and reorder buttons are disabled at list boundaries. SMF-source exports rebuild animation lists when clips are renamed, duplicated, deleted, or reordered instead of silently preserving the original source list/order, and loop/sample metadata is preserved through SMF-source plus non-SMF-to-SMF export candidates.
- Author selected-bone animation keys for position/quaternion tracks through the Animate workspace: Insert, Update, Delete, Copy, Paste, Linear/Step/Quadratic interpolation, and seconds-based Snap controls update an edit layer, rebuild runtime `AnimationClip` tracks, drive the viewport mixer, feed supported SMF export/check paths, and support toolbar/Ctrl+Z/Ctrl+Y undo-redo for key Insert/Update/Delete/Paste plus interpolation changes. Quadratic is preserved as SMF animation interpolation metadata and previews with Three.js linear track interpolation because Three has no quadratic keyframe mode. Snap is off by default and, when enabled, applies consistently to scrub/insert, paste, authored marker drag-to-time, and Animate-owned viewport key creation.
- Validate, rename, reparent, create child bones, move/rotate selected bones, and delete unweighted non-root branches for loaded non-SMF rigs in the Rig workspace. The Rig panel reports bone and skinned-mesh counts plus pass/warning/error rows for missing skeletons, duplicate bone names, orphan parents, self-parent/cycle hazards, incomplete skin attributes, mismatched skin attributes, and skin indices that reference missing bones. Selected-bone rename is enabled for non-SMF sources and retargets runtime animation tracks, authored animation key edits, pose edit keys, and selected skin-paint bone state together. Selected-bone reparent is enabled for non-SMF sources, rejects cycles/self-parenting, and preserves the bone world transform while changing hierarchy. Selected-bone create child is enabled for non-SMF sources through both the form action and the Rig Add child tool: Top/Front/Side pane clicks project a new uniquely named child under the selected parent, initialize inverse bind data, refresh Skeleton buffers, select the new child, and remain exportable through the generated-skinned SMF roundtrip path. Perspective-pane Add child clicks remain selection-only. The Rig Snap selector supports off/0.05/0.1/0.25/0.5/1 unit steps and applies to Add child placement plus Rig Move world positions. The Rig Move and Rotate tools drag the selected bone from Top/Front/Side panes through a single undoable history transaction while preserving skeleton buffers and selected skin-paint state; the explicit Endpoint tool owns cyan endpoint drags so Select/gizmo and endpoint gestures cannot conflict. Selected-bone delete blocks roots and weighted skin references, compacts Skeleton data, remaps surviving skinIndex attributes, removes deleted animation tracks/authored keys/pose edits, and selects the deleted bone's parent. Non-SMF rig rename/reparent/create/move/rotate/delete actions now use toolbar/Ctrl+Z/Ctrl+Y undo-redo snapshots that restore skeleton bones, parent links, inverse binds, skin indices, base clips, authored animation edits, pose edits, selected bone, and selected skin-paint state. SMF-source node rename/reparent/create/move/rotate/delete edits are blocked to preserve node-index and head-node export fidelity.
- Pose a selected deform bone with the explicit Rig IK tool for both SMF and non-SMF sources. The labeled target uses camera-plane dragging in any pane; settings bound chain length, CCD iterations, target tolerance, reference-pose joint angle, and world-axis pole direction. The solver validates ordered/current ancestry, reports reached/unreachable/constrained/iteration-limit states, rotates ancestors without changing local bone translations or lengths, restores the full chain on Escape/pointer cancel, and commits one pose-history transaction per completed drag. The tested pointer owner is `rig-ik-drag`, and IK temporarily detaches TransformControls. Solved rotations are marked as pose edits for high-fidelity SMF export and remain live for GLB export; SMF structural edits stay blocked.
- Inspect and select bones through the hierarchy or routed viewport clicks, with larger diamond/joint helpers, selected/hover markers, quick Rig/Skin nudges, and selected-bone weight preview. `viewportInteractionRouter.ts` assigns `model-select`, `rig-select`, `rig-endpoint-drag`, `skin-paint`, `animate-select`, `orbit`, or `none` before mutation; its click contract rejects drags, long presses, button mismatches, and out-of-pane releases. Single/quad smoke covers pane roles, real bone selection, Endpoint pose mutation, Skin paint mutation, Animate selection/key authoring, and selected-bone preservation across orbit gestures.
- TransformControls mount the public `getHelper()` scene root and expose helper/handle/axis/owner/attached/dragging telemetry. Rig Select records pose history and Animate records selected-bone keys; View, Export, Skin, quad, and ortho detach the one-camera gizmo. Skin intentionally owns paint input exclusively so a brush gesture cannot move a bone through an overlapping gizmo. Endpoint and IK also detach the gizmo and own their marked targets.
- Pose transactions from quick nudges, TransformControls, and completed Endpoint drags share toolbar/keyboard Undo/Redo and update the SMF pose-edit map. Endpoint pointer-cancel restores its pre-drag snapshot without history. Skin set/add/subtract/Auto strokes use selected-bone gating, vertex/triangle targets, bounded brush telemetry and throttling, skinned-world candidate indexing, undoable snapshots, Normalize, and configurable Auto Skin algorithms; supported dirty skin edits serialize through SMF export.
- Move the selected deform-bone endpoint with the explicit Rig Endpoint tool and a camera-plane constrained drag. The interaction does not swap models or overlap the Select gizmo; e2e smoke covers completed single/quad pose transactions plus pointer-cancel restoration without dirty state.
- Export SMF sources through the high-fidelity SMF roundtrip path, including live position/rotation pose edits from inspector nudges, TransformControls, endpoint drags, and Rig IK. SMF scale mode is refused in the UI, and any recorded non-identity pose scale blocks SMF export/roundtrip instead of being dropped.
- Export the currently loaded root and its animation clips through the explicit toolbar GLB action, independent of source-aware Export behavior. Both generic and explicit GLB paths reparse the produced bytes before save, reject non-finite transforms/tracks or missing targets, and require bone, skinned-mesh, clip, name, and track counts to survive the roundtrip. SMF animation conversion treats serialized frames as rig-space/world poses and derives each GLB track relative to its effective deform parent, including hierarchies with non-deform head/dummy nodes.
- Export compatible skinned GLB/FBX runtime roots to SMF through `threeToSmf`; use GLB export for static/material/scale cases.
- Export FBX-loaded runtime roots to binary FBX 7500 through the vendored MIT `FBXExporter-threejs` writer; static binary output is covered by a header and loader roundtrip unit test.
- Run structured SMF compatibility diagnostics before non-SMF SMF export. The Export workspace reports ready/blocked state, diagnostic error/warning counts, and specific issues such as missing skeletons, unsupported scale tracks, missing UVs/normals, missing skin attributes, non-power-of-two textures, multi-material meshes, and multi-texture material layouts. It also shows a compact material texture list with map type, name, mesh/material slot, resolution, power-of-two status, and runtime source. The Export workspace can run an in-memory SMF roundtrip check that exports, reimports, compares summary counts, geometry, bounds, animation timing/metadata, first/last-frame pose checks, and the top worst pose-delta rows with animation/frame/bone, parent/isBone, and component-delta details, then save the diagnostics/roundtrip report through the existing save bridge. Importable real-SMF fixtures with prebuilt head nodes and DQ sign flips now pass the strict structured roundtrip diagnostics.
- Cover default non-SMF skinned load/export e2e with a generated self-authored skinned GLB fixture.
- Cover basic FBX parsing with a self-authored static ASCII FBX fixture, and true binary FBX export with a self-authored static scene unit roundtrip.
- Use Rust/Tauri commands for native open/save, binary read/write, and small SMF header/rig/anim/model validation/status peeks. Desktop open is format-aware: all path-backed non-SMF models now route through `readBinaryFile`, while `.smf` still performs `get_smf_desktop_info` validation before parse. Rust SMF header/section parsing now lives in `source/src-tauri/src/smf_core.rs` with typed `SmfHeaderSummary` / `SmfDesktopInfo` output and tests for missing terminators, bad versions, invalid offsets, valid fixtures, and count-width behavior.
- Ignore stale file-open and browser file/drop read results when a newer operation has started (covered by native mocked-open/rapid-export checks and browser file-input/drop overlap smoke assertions).
- Keep editor mode + viewport layout transitions on the same shared model/viewport root; selected bone, scrub/timeline state, endpoint telemetry, and endpoint hover state are preserved across rapid single/quad transitions and covered by smoke assertions.
- Keep constrained-width workspace tabs deterministic after model load; the 360px smoke path clicks Model/Rig/Skin/Animate/Export without forced clicks and verifies selected bone plus scrub continuity.
- Model/load/export async failures in `useLoadModel` normalize unknown error values through a single helper; GLB/FBX skinned traversal, viewport transform edit events, TransformControls drag events, and Three disposal boundaries use typed guards instead of broad production `any` casts.
- `run.ps1 -Task verify` and `npm run verify` now include `check:production-any`, which fails new production `as any`, `: any`, or typed-catch `any` usages outside tests and vendored code.
- Modernization keeps the current React/Tauri/Three stack, uses GLB/GLTF as the preferred modern fidelity format, and preserves SMF for backwards compatibility. Old GameMaker screenshots/scripts now guide the remaining authoring parity work: SMF head-node-aware rig metadata edits, rig mirror/reset helpers, and deeper ortho-pane editing controls. Quad layout, pane labels/dividers, pane-role pointer telemetry, narrow Display-menu flow, model-safe wireframe display, viewport-only Legacy SMF-lit display materials, display-only no-pick skinned vertex point overlays, viewport-only selected-object overlays, grouped Display menu toggles, submodel visibility/color cues, endpoint handles, imported/authored keyframe markers, timeline lane gestures, linear/step/quadratic animation interpolation controls, loop/sample clip metadata controls, autoskin algorithm/options controls, Auto Paint brush mode, skinned-world brush indexing, normalize batch tools, Rig validation/rename/reparent/create/delete/Add child/Move/Rotate tools with snap where applicable and undo-redo, Detach/Connect buttons with hierarchy visibility/edit gating, Spin buttons with undo-redo, and pane-aware timing are current editor affordances covered by e2e/visual checks.

## Architecture

- `source/frontend/src/App.tsx`: thin shell wiring toolbar, viewport, inspector, timeline, outliner, drop zone, status, error banner, derived outliner items, active animation keyframe summaries, and animation authoring handlers.
- `source/frontend/src/hooks/useLoadModel.ts`: load/export orchestration, source format tracking, Tauri lazy imports, load/open stale guards, selected bone handling, pose edit persistence, viewport transform edit handling, shared pose/rig/animation-key/animation-workspace history snapshot/apply wiring, SMF scale-edit blocking, transform mode, and weight preview state.
- `source/frontend/src/hooks/useLoadModel.ts`: loader path now resolves a typed `TauriClient` contract (`../backend-client/tauri`) and uses a shared typed `LoadedModelResult`, reducing `any` usage across load/export/peek branches.
- `source/frontend/src/hooks/useLoadModel.ts`: in-flight export/save guard (`isExportingRef` + export seq guard) serializes export actions during async save/write and blocks stale completions.
- `source/frontend/tests/native.spec.ts`: added Playwright native IPC race coverage for delayed native saves to prove single-flight export behavior and status-button recovery under rapid click.
- `source/frontend/src/hooks/poseEdits.ts`: nudge delta types, dirty absolute-edit flags, unsupported scale flags, and helpers for live SMF position/rotation edits.
- `source/frontend/src/utils/editorHistory.ts`: shared bounded undo/redo stack helper currently used by pose authoring, non-SMF rig edits, selected-bone animation key edits, and Outliner visibility transactions; it carries ordering metadata so app-level toolbar/keyboard Undo/Redo can route by newest transaction across editor, Skin, and Outliner stacks.
- `source/frontend/src/components/ThreeViewport.tsx`: renderer, scene, camera, orbit, model attach/dispose, mixer, modern skeleton helper, helper-mesh/raycast bone picking, marker, TransformControls, typed transform edit event emission, model-safe wireframe render override, and weight preview.
- `source/frontend/src/utils/modernSkeletonHelper.ts`: typed port of the useful old helper idea, drawing larger diamond bone spans and joint markers with bone metadata for direct helper-hit selection.
- `source/frontend/src/utils/legacySmfLighting.ts`: viewport-only SMF-lit display material clone helper for the Display menu Legacy mode; original/export materials are restored and not mutated by the display toggle.
- `source/frontend/src/utils/skinPointOverlay.ts`: viewport-only skinned vertex point overlay for the Display menu Skin pts mode; points are sampled from skin attributes and colored by selected-bone influence without changing mesh/export data, are marked display-only, and opt out of raycast picking.
- `source/frontend/src/utils/selectionOverlay.ts`: viewport-only selected-object BoxHelper overlays for Outliner/model-pick selection state; overlays are not attached to export data and are rebuilt when selection or submodel visibility changes.
- `source/frontend/src/utils/skinWeights.ts`: pure skin-weight edit helpers and `SkinEditState` model for reading, setting, adding, subtracting, clamping, normalizing, typed Auto Skin/Auto Paint algorithms/options, touched-vertex snapshots, dirty tracking, and producing an explicit dirty-export block reason before UI/export wiring.
- `source/frontend/src/utils/skinBrushIndex.ts`: CPU cell indexes for bounded brush candidate queries in local bind space and skinned world space; `ThreeViewport` uses the skinned-world path for active Skin paint queries and still verifies candidates with world-space radius/depth checks before painting.
- `source/frontend/src/utils/rigValidation.ts`, `source/frontend/src/utils/rigEdits.ts`, `source/frontend/src/utils/rigHierarchy.ts`, and `source/frontend/src/components/RigPanel.tsx`: pure rig validation, selected-bone rename validation/animation retargeting, selected-bone reparent validation/world-transform preservation, selected-bone create-child validation/Skeleton initialization, selected-bone move/snap helpers, spin X/Y/Z controls for old 90-degree whole-rig transforms, selected-bone delete validation/Skeleton compaction/skinIndex remapping, pure detach/connect helper coverage for non-SMF hierarchy/deform-skeleton membership changes, shared hierarchy-bone display collection for detached-node visibility, detached hierarchy name reservation for rename/create safety, deform-bone name collection for edit-control gating, and Rig workspace report/edit rows for skeleton graph and skin-reference hazards.
- `source/frontend/src/components/Inspector.tsx`: typed skeleton tree, detached hierarchy-node display, clip list, selection controls, transform mode controls, and nudge controls.
- `source/frontend/src/components/Outliner.tsx`: model-derived submodel list with multi-select, display-only visibility toggles, bulk visibility actions, toolbar/keyboard visibility undo-redo, and material/color cues.
- `source/frontend/src/components/Timeline.tsx` / `source/frontend/src/components/AnimatePanel.tsx`: playback controls, scrub/keyframe lane, lane click-to-scrub, double-click selected-bone insertion, authored marker drag-to-time, selected-key state, imported/authored keyframe markers, active clip/selected-bone summary, keyframe authoring controls, Snap authoring control, and active-clip rename/duplicate/delete/reorder controls.
- `source/frontend/src/components/ExportPanel.tsx`: source-format and skeleton summary, structured SMF diagnostics for export preflight, material texture summary rows, in-memory SMF roundtrip status/check rows, worst-pose-delta detail rows, and diagnostic report save control.
- `source/frontend/src/utils/viewportLayout.ts`: shared single/quad viewport pane math, ortho camera framing, pointer coordinate conversion helpers, and pane-role contract used by `ThreeViewport.tsx`.

- `source/frontend/tests/helpers/skinned-glb-fixture.ts`: generated self-authored skinned GLB fixture for default non-SMF skinned e2e coverage.

## Current Limits

- Rig IK is currently a pose tool, not an Animate-workspace keyframe tool. Use Animate-owned TransformControls for authored animation keys; keyed IK needs an explicit bake-to-key design so solving cannot silently overwrite imported animation ownership.
- Native UI roundtrip automation is covered through deterministic Playwright Tauri IPC mocks plus Rust command tests; true OS dialog automation is deferred until a dialog-only bug, CI requirement, or release checklist needs it.
- Default non-SMF skinned coverage uses a generated skinned GLB fixture. FBX coverage uses a self-authored static ASCII FBX fixture for parser coverage plus a generated static scene for binary FBX export roundtrip; skinned FBX fidelity still needs a dedicated redistributable skinned FBX asset if that path becomes important.
- GLB/FBX-to-SMF conversion is available for skinned models with one shared named skeleton and no scale animation. Static roots, textures/materials, morph tracks, object-level tracks, and scale animation still use GLB export for fidelity. SMF diagnostics now block known impossible exports before save, surface warnings for material/texture compatibility risks that do not block, show texture source summaries, and provide a structured in-memory roundtrip check for count, geometry, bounds, animation timing/metadata, first/last-frame pose deltas, and bounded worst-pose-delta details. Importable real SMF samples covered by `mixamo_smf_baldguy.smf` and old-source `spider_TEST.smf` pass strict import/export/reimport diagnostics; older unsupported version strings and malformed/truncated legacy files remain explicit import-compatibility limits rather than roundtrip failures.
- GLB/GLTF remains the preferred format for maximum fidelity and new development. SMF support is scoped to legacy recovery and users who target the old SMF binary pipeline.
- Live SMF position/rotation pose edits export; scale edits are blocked for SMF export because the current SMF DQ path has no scale channel. The UI refuses SMF scale mode, and export/roundtrip guards also catch recorded non-identity scale.
- Quad layout, ortho camera panes, single-view Ortho, visible pane labels/dividers, narrow Display-menu flow that stays clear of quad labels, model-safe wireframe display, Legacy SMF-lit viewport display, display-only no-pick Skin pts vertex overlay, selected-object viewport overlays, grouped Display menu toggles, Outliner submodel visibility/color cues, Outliner multi-select/bulk visibility with undo-redo, View-mode model/submodel picking, larger diamond/joint rig helpers, the explicit Endpoint tool, imported/authored keyframe markers, timeline lane click-to-scrub, double-click selected-bone insertion, authored marker drag-to-time with optional snap, selected-bone keyframe authoring with linear/step/quadratic interpolation and toolbar/keyboard undo-redo, active-clip rename/duplicate/delete/reorder/loop/sample metadata controls with toolbar/keyboard undo-redo, real TransformControls handle proof for Rig-pose versus Animate-key ownership, Rig validation/rename/reparent/create/delete/Add child/Move/Rotate/Detach/Connect/Spin with snap where applicable plus toolbar/keyboard undo-redo, pointer-owner routing, app-level chronological Undo/Redo across editor/Skin/Outliner stacks, and pose undo/redo for nudges/gizmo/endpoint edits are implemented and covered by focused e2e/visual checks. Skin paint authoring covers stroke undo/redo through local controls plus toolbar/Ctrl+Z/Ctrl+Y, empty-space miss safety, Auto Paint brush mode, skinned-world brush candidate indexing, vertex/triangle targets, autoskin algorithm/options, normalize batch actions, state continuity, and supported export behavior; pure non-SMF detach/connect, spin, and rotate helpers are tested, Detach/Connect UI is smoke-covered for hierarchy visibility, deform-edit gating, and undo/redo skeleton membership restoration, Spin UI is smoke-covered for one-transaction undo/redo, and Rotate UI is smoke-covered for one-transaction undo/redo. SMF head-node-aware rig metadata edits, rig mirror/reset helpers, and deeper ortho-pane editing parity remain planned; the freeform TransformControls gizmo is intentionally single-perspective until it can own a pane-specific camera.
- Launcher process safety (no rogue node servers on close) is Windows-primary via run.ps1 + mjs layers (Job/tree/scans/poll). Direct `tauri dev` or non-Windows have reduced coverage (mjs signals + polls + child-tree cleanup where supported); behavior is documented explicitly in launcher docs.
