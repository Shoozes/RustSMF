# RustSMF App State

Last reviewed: 2026-07-30 (completed the Original SMF quad-default, shared viewport-focus panning, and source-texture thumbnail follow-up while retaining the verified theme, FBX, SMF, worker, async-ownership, workspace-continuity, and load/edit/export contracts).

## Current Product State

RustSMF is a Tauri + React + Three.js desktop/web model tool for SMF, GLB/GLTF, FBX, and OBJ workflows.

Core flow:
- Launch from `.\run.bat` or `pwsh -File run.ps1`; no-argument launch opens the numbered menu. Choose option 2, or run `.\run.bat 2` / `pwsh -File run.ps1 -Task run`, to start the desktop app when dependencies are already installed.
- Load `.smf`, `.glb`, `.gltf`, `.fbx`, and `.obj` through browser input, drag/drop, or Tauri native dialog.
- Parse and export SMF through a dedicated typed Web Worker with transferable buffers, runtime validation of the request operation and nested SMF payload, monotonic visible progress, a 120-second timeout, abort/termination cleanup, structured errors, and latest-intent checks before model or save ownership can commit. Only worker construction or initial `postMessage` failure may use the explicitly labeled synchronous fallback; runtime worker failures surface instead of silently repeating expensive work on the UI thread.
- The Outliner derives real model items from the loaded Three root, shows mesh/group counts, bounded source base-color texture thumbnails with material-color fallback, vertex/material hints, selected row state, and display-only submodel visibility toggles. It supports row multi-select, Select All, Clear, Hide selected, Hide unselected, Show all, View-mode viewport mesh picking/context readiness against the same model item list, viewport-only selection overlays for selected visible objects, and toolbar/keyboard undo-redo for visibility transactions. App-level Undo/Redo now chooses the newest available editor, skin, or outliner transaction by shared chronology instead of current workspace bias.
- Render model roots in a self-contained Three.js viewport with orbit, wheel zoom, right-drag pan, reset, lighting, grid, axes, model-safe wireframe render override, resize handling, and identity-deduplicated geometry/material/texture/skeleton cleanup.
- Validate Tauri dialog results, DOM selector values, Three object kinds, exporter binary results, animation arrays, material properties, and disposable resources through narrow guards/adapters instead of broad production assertions. Literal `as const` narrowing remains; production `any`, double assertions, and broad Three/DOM casts are absent outside the owned vendor boundary.
- Viewport layout controls are model-aware: before a model loads, the visible layout follows the active theme default (Modern single, Original SMF quad) while the single/quad controls remain disabled; controls become active after a model is loaded. Camera mode is exposed as a compact 3D/Ortho switch, with single-view orthographic framing sized to the active canvas. Quad view is visually explicit with pane dividers and Top/3D/Front/Side labels. Every pane uses one shared world-space focus target: right-dragging any orthographic view pans in that view plane and re-centers the perspective camera, while perspective panning re-centers all fixed views without changing their directions or zoom. At narrow widths, an open Display menu stays in the toolbar flow so it does not overflow horizontally or cover quad pane labels. Shared pane hit math now uses deterministic half-open internal boundaries, inclusive outer canvas edges, CSS-coordinate normalization that remains stable under high-DPI backing buffers, and browser-visible `data-viewport-pane-role` telemetry for the pane hit by the latest routed pointer event.
- Mode/workspace switching is continuity-checked in normal, medium, and constrained-width viewports; narrow layouts put mode tabs on a scrollable row, and layout switching remains disabled until a model is loaded. A loaded-authoring matrix also proves one model root, object/bone selection, paused playback time, export status, pose/skin/animation dirty state, and Select/Endpoint/IK handle ownership across single, quad, Ortho, and View/Rig/Skin/Animate/Export transitions. The viewport exposes read-only root/playback telemetry so shared state remains observable while panels such as Timeline are intentionally unmounted.
- Choose between the default Modern theme and a persisted Original SMF theme through the toolbar. The typed registry rejects stale stored values and keeps theme storage failure non-blocking. Original SMF restores the preserved editor frame without forking editor state: a 136 px Settings/tool shelf, 128 px Submodels shelf, 80 px two-row top strip, fixed numbered red mode tabs, dense square controls, charcoal viewports, camera-aligned red/black grids in every quad pane, legacy-scale orthographic framing, quad view by default both before and after model load, and the timeline in the center top shelf only in Animation. The Submodels shelf renders bounded thumbnails from each source material's actual base-color texture, including raw SMF `DataTexture` pixels, with the material color as the untextured/unsupported fallback. The Original keyframe strip follows the old source geometry with a 128 px tool inset, 16 px right inset, 28 px normalized ruler, 32 px marker band, multiplier-derived blue sample divisions, 10 px green keys, red selection, and a playing-only blue playhead; rendered sample density is capped at 512 for legibility and responsiveness. Before load, theme switches always apply the new theme default; after load, they carry that default only while the current layout still matches the previous theme default, so an explicit non-default layout choice is preserved. Narrow Original SMF layouts prioritize the viewport and stack tools below it without horizontal overflow.
- Launcher contract (current):
  - `run.bat` / `run.ps1` are the canonical Windows workflow and carry full orphan-prevention coverage.
  - `run.ps1 -Task run` (same as launcher option 2) is the default app launch path after setup.
  - `run.ps1 -Task test:e2e` uses GenEye as an optional advisory Playwright subagent when discoverable, but RustSMF remains able to run browser-only e2e with `-NoGenEye`, `RUSTSMF_NO_GENEYE=1`, or no GenEye checkout/runtime.
  - Direct `npm run dev` / `npm run tauri:dev` flows remain available but intentionally have reduced non-canonical lifecycle guarantees.
- Drive animation through viewport-owned `AnimationMixer` state with timeline play/pause, scrub, speed, clip selection, imported keyframe markers, lane click-to-scrub, double-click selected-bone key insertion, authored marker drag-to-time, and an Animate workspace summary for active clip/selected-bone tracks. Mixer actions are root-affine during model replacement, and a newly attached root receives the current clip, pause, time, and speed as one playback intent instead of briefly binding new tracks to the prior root.
- Manage the active animation clip from the Animate workspace with rename, duplicate, guarded delete, Move Up/Move Down reorder, loop toggle, and sample frame multiplier controls. Clip CRUD/reorder/metadata edits update the base clip list or metadata edit layer, authored animation edit keys where applicable, active playback clip/time, and toolbar/Ctrl+Z/Ctrl+Y editor history together; delete is disabled for the final remaining clip and reorder buttons are disabled at list boundaries. SMF-source exports rebuild animation lists when clips are renamed, duplicated, deleted, or reordered instead of silently preserving the original source list/order, and loop/sample metadata is preserved through SMF-source plus non-SMF-to-SMF export candidates.
- Author selected-bone animation keys for position/quaternion tracks through the Animate workspace: Insert, Update, Delete, Copy, Paste, Linear/Step/Quadratic interpolation, and seconds-based Snap controls update an edit layer, rebuild runtime `AnimationClip` tracks, drive the viewport mixer, feed supported SMF export/check paths, and support toolbar/Ctrl+Z/Ctrl+Y undo-redo for key Insert/Update/Delete/Paste plus interpolation changes. Quadratic is preserved as SMF animation interpolation metadata and previews with Three.js linear track interpolation because Three has no quadratic keyframe mode. Snap is off by default and, when enabled, applies consistently to scrub/insert, paste, authored marker drag-to-time, and Animate-owned viewport key creation.
- Validate, rename, reparent, create child bones, move/rotate selected bones, and delete unweighted non-root branches for loaded non-SMF rigs in the Rig workspace. The Rig panel reports bone and skinned-mesh counts plus pass/warning/error rows for missing skeletons, duplicate bone names, orphan parents, self-parent/cycle hazards, incomplete skin attributes, mismatched skin attributes, and skin indices that reference missing bones. Selected-bone rename is enabled for non-SMF sources and retargets runtime animation tracks, authored animation key edits, pose edit keys, and selected skin-paint bone state together. Selected-bone reparent is enabled for non-SMF sources, rejects cycles/self-parenting, and preserves the bone world transform while changing hierarchy. Selected-bone create child is enabled for non-SMF sources through both the form action and the Rig Add child tool: Top/Front/Side pane clicks project a new uniquely named child under the selected parent, initialize inverse bind data, refresh Skeleton buffers, select the new child, and remain exportable through the generated-skinned SMF roundtrip path. Perspective-pane Add child clicks remain selection-only. The Rig Snap selector supports off/0.05/0.1/0.25/0.5/1 unit steps and applies to Add child placement plus Rig Move world positions. The Rig Move and Rotate tools drag the selected bone from Top/Front/Side panes through a single undoable history transaction while preserving skeleton buffers and selected skin-paint state; the explicit Endpoint tool owns cyan endpoint drags so Select/gizmo and endpoint gestures cannot conflict. Selected-bone delete blocks roots and weighted skin references, compacts Skeleton data, remaps surviving skinIndex attributes, removes deleted animation tracks/authored keys/pose edits, and selects the deleted bone's parent. Non-SMF rig rename/reparent/create/move/rotate/delete actions use toolbar/Ctrl+Z/Ctrl+Y snapshots that restore skeleton bones, parent links, inverse binds, skin indices, base clips, authored animation edits, pose edits, selected bone, and selected skin-paint state. For SMF sources, a visible format-policy panel explains that rename cannot persist because SMF has no name field, detach/connect is structural, and mirror has no owned legacy command or left/right metadata. Those controls remain absent or disabled. Bind reset is enabled because it restores only the selected deform bone's local bind transform from inverse binds; it is undoable and preserves indexed node/head/skin/animation identity.
- Pose a selected deform bone with the explicit Rig IK tool for both SMF and non-SMF sources. The labeled target uses camera-plane dragging in any pane; settings bound chain length, CCD iterations, target tolerance, reference-pose joint angle, and world-axis pole direction. The solver validates ordered/current ancestry, reports reached/unreachable/constrained/iteration-limit states, rotates ancestors without changing local bone translations or lengths, restores the full chain on Escape/pointer cancel, and commits one pose-history transaction per completed drag. The tested pointer owner is `rig-ik-drag`, and IK temporarily detaches TransformControls. Solved rotations are marked as pose edits for high-fidelity SMF export and remain live for GLB export; SMF structural edits stay blocked.
- Inspect and select bones through the hierarchy or routed viewport clicks, with larger diamond/joint helpers, selected/hover markers, quick Rig/Skin nudges, and selected-bone weight preview. `viewportInteractionRouter.ts` assigns `model-select`, `rig-select`, `rig-endpoint-drag`, `skin-paint`, `animate-select`, `orbit`, or `none` before mutation; its click contract rejects drags, long presses, button mismatches, and out-of-pane releases. Single/quad smoke covers pane roles, real bone selection, Endpoint pose mutation, Skin paint mutation, Animate selection/key authoring, and selected-bone preservation across orbit gestures.
- TransformControls mount the public `getHelper()` scene root and expose helper/handle/axis/owner/attached/dragging telemetry. Rig Select records pose history and Animate records selected-bone keys; View, Export, Skin, quad, and ortho detach the one-camera gizmo. Skin intentionally owns paint input exclusively so a brush gesture cannot move a bone through an overlapping gizmo. Endpoint and IK also detach the gizmo and own their marked targets.
- Pose transactions from quick nudges, bind reset, TransformControls, and completed Endpoint drags share toolbar/keyboard Undo/Redo and update the SMF pose-edit map. Bind reset removes the selected bone from the SMF pose-edit map only after restoring its actual local bind transform; it never assumes a zero local transform. Endpoint pointer-cancel restores its pre-drag snapshot without history. Skin set/add/subtract/Auto strokes use selected-bone gating, vertex/triangle targets, bounded brush telemetry and throttling, skinned-world candidate indexing, undoable snapshots, Normalize, and configurable Auto Skin algorithms; supported dirty skin edits serialize through SMF export.
- Move the selected deform-bone endpoint with the explicit Rig Endpoint tool and a camera-plane constrained drag. The interaction does not swap models or overlap the Select gizmo; e2e smoke covers completed single/quad pose transactions plus pointer-cancel restoration without dirty state.
- Export SMF sources through the high-fidelity SMF roundtrip path, including live position/rotation pose edits from inspector nudges, TransformControls, endpoint drags, and Rig IK. Edited child DQs are serialized from rig-space `matrixWorld`, so effective-parent chains that skip non-deform head nodes remain correct. SMF skin indices remain in sequential deform-bone order across export/reimport; full node IDs are not written into the skin payload. SMF scale mode is refused in the UI, and any recorded non-identity pose scale blocks SMF export/roundtrip instead of being dropped.
- Export the currently loaded root and its animation clips through the explicit toolbar GLB action, independent of source-aware Export behavior. Both generic and explicit GLB paths reparse the produced bytes before save, reject non-finite transforms/tracks or missing targets, and require bone, skinned-mesh, clip, name, and track counts to survive the roundtrip. SMF animation conversion treats serialized frames as rig-space/world poses and derives each GLB track relative to its effective deform parent, including hierarchies with non-deform head/dummy nodes.
- Keep Display state out of saved assets. Tex, Mesh fade, Legacy lighting, repeat wrapping, source/nearest/linear filtering, and selected-bone weight colors are viewport previews. GLB/FBX export restores source mesh-material assignments, texture maps, opacity/transparency, vertex colors, geometry color attributes, wrap modes, and filters for the full async exporter call, then reapplies the active preview only if the same root is still mounted. The Export workspace states per-action texture behavior: SMF-source SMF embeds imported RGBA records, binary GLB embeds supported images, browser/desktop FBX requests embedded images, and non-SMF-to-SMF conversion omits textures with GLB recommended for material fidelity.
- Export compatible skinned GLB/FBX runtime roots to SMF through `threeToSmf`; indexed geometry is expanded through one validated triangle map so positions and every optional vertex attribute reach SMF as aligned triangle soup. Use GLB export for static/material/scale cases.
- Export the current runtime root and clips through the explicit toolbar FBX action, independent of source-aware Export behavior. FBX sources still select FBX through the primary Export action. Both paths use the vendored MIT `FBXExporter-threejs` writer with materials, supported embedded images, skins, animation clips, visibility filtering, and source-material restoration. Before save, exported bytes must pass binary header/version checks, reparse, finite-transform/track checks, and representative mesh/skin/bone/clip preservation.
- Run structured SMF compatibility diagnostics before non-SMF SMF export. The Export workspace reports ready/blocked state, diagnostic error/warning counts, and specific issues such as missing skeletons, unsupported scale tracks, missing UVs/normals, missing skin attributes, non-power-of-two textures, multi-material meshes, and multi-texture material layouts. It also shows a compact material texture list with map type, name, mesh/material slot, resolution, power-of-two status, runtime source, and cross-material shared-texture groups. Shared groups are a preflight only: RustSMF does not reproduce the legacy destructive geometry/material merge without an undoable validated atlas workflow. Global snap is likewise retired in favor of Rig world-unit and Animate time-unit settings. The Export workspace can run an in-memory SMF roundtrip check that exports, reimports, compares summary counts, geometry, skin indices, 8-bit skin-weight tolerance, bounds, animation timing/metadata, first/last-frame pose checks, and the top worst pose-delta rows with animation/frame/bone, parent/isBone, and component-delta details, then save the diagnostics/roundtrip report through the existing save bridge. Importable real-SMF fixtures with prebuilt head nodes and DQ sign flips pass the strict structured roundtrip diagnostics.
- Cover default non-SMF skinned load/export e2e with a generated self-authored skinned GLB fixture.
- Cover basic FBX parsing with a self-authored static ASCII FBX fixture, true binary FBX export with a self-authored static scene unit roundtrip, and explicit generated skinned GLB -> FBX download -> app re-import in Playwright.
- Use Rust/Tauri commands for native open/save, binary read/write, and small SMF header/rig/anim/model validation/status peeks. Desktop open is format-aware: all path-backed non-SMF models now route through `readBinaryFile`, while `.smf` still performs `get_smf_desktop_info` validation before parse. Rust SMF header/section parsing now lives in `source/src-tauri/src/smf_core.rs` with typed `SmfHeaderSummary` / `SmfDesktopInfo` output and tests for missing terminators, bad versions, invalid offsets, valid fixtures, and count-width behavior.
- Treat picker open, browser file input, drag/drop, desktop validation/read, loader completion, and export/save completion as one ordered lifecycle. Every load intent advances one shared load sequence and invalidates older export UI commits; stale parsed roots are disposed. Successful loads replace the prior model atomically only after parse, while failed replacements preserve the current root, selection, and dirty authoring state. Delayed success/error matrices cover picker, browser read, desktop path read, diagnostic/model save single-flight, and export-versus-newer-load ownership.
- Keep editor mode + viewport layout transitions on the same shared model/viewport root; root identity, selected object/bone, paused playback time, export status, pose/skin/animation dirty state, and Select/Endpoint/IK ownership are preserved across single/quad/Ortho and all workspace modes. Native canceled-save coverage also cycles panels before proving the same root, status, selection, and dirty edit remain intact.
- Keep constrained-width workspace tabs deterministic after model load; the 360px smoke path clicks Model/Rig/Skin/Animate/Export without forced clicks and verifies selected bone plus scrub continuity.
- Model/load/export async failures in `useLoadModel` normalize unknown error values through a single helper. Focused modules own codec task lifecycle, export-candidate policy, and editor snapshot capture/apply; GLB/FBX skinned traversal, viewport transform edit events, TransformControls drag events, and Three disposal boundaries use typed guards instead of broad production `any` casts.
- `run.ps1 -Task verify` and `npm run verify` now include `check:production-any`, which fails new production `as any`, `: any`, or typed-catch `any` usages outside tests and vendored code.
- Modernization keeps the current React/Tauri/Three stack, uses GLB/GLTF as the preferred modern fidelity format, and preserves SMF for backwards compatibility. Old GameMaker screenshots/scripts now guide the remaining authoring parity work around deeper ortho-pane editing controls; SMF Rig metadata/reset and global shelf/material decisions are complete. Quad layout, shared-target perspective/ortho panning, pane labels/dividers, pane-role pointer telemetry, narrow Display-menu flow, model-safe wireframe display, viewport-only Legacy SMF-lit display materials, sampler previews, display-only no-pick skinned vertex point overlays, viewport-only selected-object overlays, grouped Display menu toggles, submodel visibility/texture-color cues, endpoint handles, imported/authored keyframe markers, timeline lane gestures, linear/step/quadratic animation interpolation controls, loop/sample clip metadata controls, autoskin algorithm/options controls, Auto Paint brush mode, skinned-world brush indexing, normalize batch tools, Rig validation/rename/reparent/create/delete/Add child/Move/Rotate tools with snap where applicable and undo-redo, Detach/Connect buttons with hierarchy visibility/edit gating, Spin buttons with undo-redo, and pane-aware timing are current editor affordances covered by e2e/visual checks.

## Architecture

- `source/frontend/src/App.tsx`: application shell wiring toolbar, viewport, inspector, timeline, outliner, drop zone, status/progress, error banner, derived outliner items, active animation keyframe summaries, and animation authoring handlers.
- `source/frontend/src/theme.ts` / `source/frontend/src/hooks/useAppTheme.ts`: typed theme registry, viewport appearance/default-layout metadata, guarded browser persistence, and the small React preference hook used by the shell and toolbar.
- `source/frontend/src/hooks/useLoadModel.ts`: the public load/export editor hook and integration owner. `useSmfCodecTask.ts` owns active worker task cancellation/progress, `smfExportCandidate.ts` owns source/candidate pose-animation-skin policy, and `editorSnapshots.ts` owns pure editor history capture/apply. The hook retains typed Tauri/loader contracts, one cross-entrypoint load sequence, atomic successful replacement, stale-root disposal, global save serialization, and UI state wiring.
- `source/frontend/tests/native.spec.ts`: deterministic delayed picker/read/write success and error matrices prove cross-entrypoint latest-intent ownership, atomic failed replacements, global save single-flight, stale export suppression, canceled-save continuity, and status/button recovery.
- `source/frontend/src/hooks/poseEdits.ts`: nudge delta types, dirty absolute-edit flags, unsupported scale flags, and rig-space world-DQ serialization helpers for live SMF position/rotation edits.
- `source/frontend/src/utils/editorHistory.ts`: shared bounded undo/redo stack helper currently used by pose authoring, non-SMF rig edits, selected-bone animation key edits, and Outliner visibility transactions; it carries ordering metadata so app-level toolbar/keyboard Undo/Redo can route by newest transaction across editor, Skin, and Outliner stacks.
- `source/frontend/src/components/ThreeViewport.tsx`: renderer, scene, perspective/fixed camera synchronization, requestAnimationFrame loop, orbit, pane-aware shared-target pan, model attach/dispose, mixer, modern skeleton helper, helper-mesh/raycast bone picking, marker, model-safe wireframe render override, and weight preview. Stable event contracts live in `types/viewportEditorEvents.ts`; mount-owned pointer/listener cleanup and current-state refs live in `viewportInteractionRuntime.ts`; TransformControls attach/detach/dispose policy lives in `viewportTransformControls.ts`.
- `source/frontend/src/utils/modernSkeletonHelper.ts`: typed port of the useful old helper idea, drawing larger diamond bone spans and joint markers with bone metadata for direct helper-hit selection.
- `source/frontend/src/utils/legacySmfLighting.ts`: viewport-only SMF-lit display material clone helper for the Display menu Legacy mode; original/export materials are restored and not mutated by the display toggle.
- `source/frontend/src/utils/materialPreview.ts`: root-scoped source/preview boundary for material assignments, maps, opacity, vertex colors, geometry color attributes, and texture sampler state; GLB/FBX exporters use its async restoration guard.
- `source/frontend/src/utils/materialPolicy.ts`: pure source-format-to-export texture policy plus explicit decisions for retired global snap, destructive texture merge, and include-textures controls.
- `source/frontend/src/utils/skinPointOverlay.ts`: viewport-only skinned vertex point overlay for the Display menu Skin pts mode; points are sampled from skin attributes and colored by selected-bone influence without changing mesh/export data, are marked display-only, and opt out of raycast picking.
- `source/frontend/src/utils/selectionOverlay.ts`: viewport-only selected-object BoxHelper overlays for Outliner/model-pick selection state; overlays are not attached to export data and are rebuilt when selection or submodel visibility changes.
- `source/frontend/src/utils/skinWeights.ts`: pure skin-weight edit helpers and `SkinEditState` model for reading, setting, adding, subtracting, clamping, normalizing, typed Auto Skin/Auto Paint algorithms/options, touched-vertex snapshots, dirty tracking, and producing an explicit dirty-export block reason before UI/export wiring.
- `source/frontend/src/utils/skinBrushIndex.ts`: CPU cell indexes for bounded brush candidate queries in local bind space and skinned world space; `ThreeViewport` uses the skinned-world path for active Skin paint queries and still verifies candidates with world-space radius/depth checks before painting.
- `source/frontend/src/utils/rigValidation.ts`, `source/frontend/src/utils/rigEdits.ts`, `source/frontend/src/utils/rigHierarchy.ts`, `source/frontend/src/utils/smfRigPolicy.ts`, and `source/frontend/src/components/RigPanel.tsx`: pure rig validation, inverse-bind local reset, selected-bone rename validation/animation retargeting, selected-bone reparent validation/world-transform preservation, selected-bone create-child validation/Skeleton initialization, selected-bone move/snap helpers, spin X/Y/Z controls for old 90-degree whole-rig transforms, selected-bone delete validation/Skeleton compaction/skinIndex remapping, pure detach/connect helper coverage for non-SMF hierarchy/deform-skeleton membership changes, shared hierarchy-bone display collection for detached-node visibility, detached hierarchy name reservation for rename/create safety, deform-bone name collection for edit-control gating, exact SMF format-policy reasons, and Rig workspace report/edit rows for skeleton graph and skin-reference hazards.
- `source/frontend/src/components/Inspector.tsx`: typed skeleton tree, detached hierarchy-node display, clip list, selection controls, transform mode controls, and nudge controls.
- `source/frontend/src/components/Outliner.tsx` / `source/frontend/src/components/TextureThumbnail.tsx`: model-derived submodel list with multi-select, display-only visibility toggles, bulk visibility actions, toolbar/keyboard visibility undo-redo, and actual source-map thumbnails with material-color fallback.
- `source/frontend/src/components/Timeline.tsx` / `source/frontend/src/components/AnimatePanel.tsx`: playback controls, scrub/keyframe lane, lane click-to-scrub, double-click selected-bone insertion, authored marker drag-to-time, selected-key state, imported/authored keyframe markers, active clip/selected-bone summary, keyframe authoring controls, Snap authoring control, and active-clip rename/duplicate/delete/reorder controls.
- `source/frontend/src/components/ExportPanel.tsx`: source-format and skeleton summary, structured SMF diagnostics for export preflight, material texture summary rows, in-memory SMF roundtrip status/check rows, worst-pose-delta detail rows, and diagnostic report save control.
- `source/frontend/src/utils/viewportLayout.ts`: shared single/quad viewport pane math, fixed-camera framing around one focus target, orthographic screen-to-world pan conversion, pointer coordinate conversion helpers, and pane-role contract used by `ThreeViewport.tsx`.
- `source/frontend/src/utils/rigIk.ts`: bounded CCD on a private cloned chain, ordered-chain validation, world/local quaternion conversion, reference-pose joint limits, pole alignment, unreachable clamping, stale-chain detection, and local-length invariants; only solved rotations are copied to live bones.
- `source/frontend/src/utils/viewportInteractionRouter.ts`: pure pointer-owner router for mode-specific viewport click/drag intent; currently wired for telemetry, View-mode model/submodel selection, Rig/Animate bone selection, Rig endpoint drag, Skin paint gating, orbit, and Export read-only left clicks.
- `source/frontend/src/utils/modelOutliner.ts`, `source/frontend/src/utils/textureThumbnail.ts`, `source/frontend/src/utils/textureCompat.ts`, `source/frontend/src/utils/animationTimeline.ts`, and `source/frontend/src/utils/animationEdits.ts`: pure helpers for model tree/source-material summaries, bounded raw-texture thumbnail sampling, material/texture compatibility summaries, imported clip keyframe summaries, editable animation keyframes, clip edit-state helpers, runtime clip rebuilding, and SMF-source dirty animation/list patching.
- `source/frontend/src/loaders/*` and `source/frontend/src/vendor/FBXExporter.js`: SMF import/export (buildThreeScene delegates rig to buildRigHierarchy for flat nodes + isBone=0 head dummies: cycle-safe effective-parent walk skips heads for direct real-bone `.add()` + deform-only Skeleton; bind locals use nearest real ancestor world for correct `matrixWorld`; inverse binds are calculated after world matrices update; animation tracks are emitted only for real scene bones; names use `SMF_Node_N` + `userData`; skin remap is direct on compressed is-bone order), bounded binary helpers, one shared deep-owned SMF clone/transfer helper, rig node-list helper, structured SMF diagnostics, guarded Three-to-SMF conversion with indexed-to-triangle-soup expansion, GLB/FBX/OBJ loading/export, validated binary FBX 7500 export, coordinate swizzles, and DQ math. SMF textures remain owned RGBA typed arrays through import/edit/export and become Three `DataTexture` objects only during scene construction. Serialization normalizes DQs into fresh buffers instead of mutating caller state; diagnostics compare normalized sign-equivalent DQs as the same serialized pose. `dqNormalize` falls back to identity for zero/NaN/Infinity rotation parts, and SMF-source export preserves prebuilt head-node rig/frame DQs.
- `source/frontend/src/workers/*`: runtime-validated SMF import/export protocol, pure worker runtime, browser worker entry, and client lifecycle. Both outer messages and nested operation-specific payloads are treated as untrusted. Import transfers caller-owned bytes; export first deep-clones the canonical SMF data so transferring worker inputs cannot detach live editor state. Unit tests cover nested rejection, progress, transfer ownership, cancellation, timeout cleanup, protocol regression, startup fallback, and runtime error behavior.
- `source/frontend/src/backend-client/tauri.ts`: centralized `TauriClient` browser/Tauri bridge for dialog, save, binary read, invokes, and desktop fallback messages. Dialog results are validated from `unknown`, and `saveFile` returns `boolean` so cancel is explicit.
- `source/frontend/src/utils/threeTypeGuards.ts` and `source/frontend/src/utils/threeDisposal.ts`: shared Three object narrowing plus one-time subtree cleanup for shared geometry, material, texture, and skeleton resources.
- `source/frontend/src/utils/modelFormat.ts`: canonical format extension parser + shared extension constants for open/load/tauri filters.
- `source/frontend/tests/helpers/skinned-glb-fixture.ts`: generated self-authored skinned GLB fixture for default non-SMF skinned e2e coverage.
- `source/frontend/src/store`: lightweight React state slices for model, playback, and UI.
- `source/src-tauri/src/main.rs` and `source/src-tauri/src/smf_core.rs`: Tauri commands plus the Rust SMF header/section parser core, desktop summary struct, and native parser tests.
- `source/backend`: reserved boundary only; no current backend service is required.
- Launchers + dev server lifecycle (`run.ps1` / `run.bat` default, `source/frontend/scripts/start-vite-dev.mjs` beforeDev wrapper, `source/src-tauri/tauri.conf.json`): stable Node/npm discovery prefers the npm CLI bundled beside the active Node executable, then safe child process handling (Windows JobObject KILL_ON_JOB_CLOSE + recursive tree kill + port 5173 + cmdline sweeps + entry stale reaper + signals + finally/traps + parent poll) prevents rogue node/Vite servers after closing the cmd window or Tauri app. Tauri CLI term of beforeDev triggers mjs cleanup; launcher owns the outer tree. See the pitfall ledger and `subsystem__dev_process_lifecycle`.
- `source/frontend/tests/*.spec.ts` and `source/frontend/tests/helpers/*`: 54 browser checks split by shell/model, lifecycle, Rig, Animate, Skin, formats, native IPC, and visual ownership. Shared fixtures and interaction helpers remain separate from domain assertions; strict snapshots live beside `shell-model.spec.ts` and `export-formats.spec.ts`.

## Current Limits

- Rig IK is currently a pose tool, not an Animate-workspace keyframe tool. Use Animate-owned TransformControls for authored animation keys; keyed IK needs an explicit bake-to-key design so solving cannot silently overwrite imported animation ownership.
- Native UI roundtrip automation is covered through deterministic Playwright Tauri IPC mocks plus Rust command tests; true OS dialog automation is deferred until a dialog-only bug, CI requirement, or release checklist needs it.
- Default non-SMF skinned coverage uses a generated skinned GLB fixture. FBX coverage uses a self-authored static ASCII FBX fixture for parser coverage plus a generated static scene for binary FBX export roundtrip; skinned FBX fidelity still needs a dedicated redistributable skinned FBX asset if that path becomes important.
- GLB/FBX-to-SMF conversion is available for skinned models with one shared named skeleton and no scale animation. Static roots, textures/materials, morph tracks, object-level tracks, and scale animation still use GLB export for fidelity. SMF diagnostics now block known impossible exports before save, surface warnings for material/texture compatibility risks that do not block, show texture source summaries, and provide a structured in-memory roundtrip check for count, geometry, bounds, animation timing/metadata, first/last-frame pose deltas, and bounded worst-pose-delta details. Importable real SMF samples covered by `mixamo_smf_baldguy.smf` and old-source `spider_TEST.smf` pass strict import/export/reimport diagnostics; older unsupported version strings and malformed/truncated legacy files remain explicit import-compatibility limits rather than roundtrip failures.
- GLB/GLTF remains the preferred format for maximum fidelity and new development. SMF support is scoped to legacy recovery and users who target the old SMF binary pipeline.
- Live SMF position/rotation pose edits export from rig-space world transforms; bind reset restores the selected deform bone's inverse-bind-derived local transform. Scale edits are blocked for SMF export because the current SMF DQ path has no scale channel. The UI refuses SMF scale mode, and export/roundtrip guards also catch recorded non-identity scale.
